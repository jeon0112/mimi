# Sentinel 을 누가 감시하나 — 넷을 만들었고, 넷 다 아직 안 돈다

**2026-09-24 · 시저님이 직접 부르신 콜에 대한 뭉클이 P1~P3 실장 보고 검토 · 안토니우스 · 원장 E-893~E-901**

---

## 0. 먼저 — 뭉클이가 잘했다

| | |
|---|---|
| **P1 Sentinel** | **양방향 시험을 했다** — 타임아웃 미실행 ✓ · 승인 실행 ✓ · **거부 `CALLBACK='no'` 실측 ✓** |
| ★ | **타임아웃이면 실행하지 않는다** = **fail-closed**. 답이 없을 때 막히는 쪽으로 만들었다. **이것이 제일 잘한 설계다** |
| **P2 레지스트리** | 전수조사 + **결함 2건을 숨기지 않고 기록**(NARA 키 VPS 없음 · push 자격 없음) |
| **P3 goals** | 아침점호 크론에 연동하고 **`jobs.json` 반영을 검증**(True) — 「걸었다」가 아니라 「걸렸나」를 확인했다 |
| **P5 감사** | 11건, **원본 대조 완료** |
| ★★★ | **「게이트 대상 목록」을 자기가 안 정하고 물었다** — 판단이 필요한 자리에서 멈췄다 |

## 1. 🔴 그런데 넷 다 「만들었다」이고 「도는가」가 없다

```
Sentinel     만들었다.  ★ 아직 아무 행동에도 안 걸려 있다  ← 뭉클이가 스스로 물었다
레지스트리   만들었다.  ★ 언제 잰 값인지·누가 다시 재는지 없다
goals.md     만들었다.  ★ 「무엇이 되면 끝인가」가 없다
감사 기록    만들었다.  ★ 누가 못 고치는지 없다
```

> ★★★★★ **E-491 — 「만들어 뒀는데, 부르는 것이 있는가」가 넷 다 걸린다.**
> **오늘 하루에 네 개를 만들었고, 네 개 다 아직 아무것도 막거나 기록하거나 끝내지 않는다.**

## 2. ★★★★★ 제일 위험한 것 — Sentinel 이 죽으면 어떻게 되나

**타임아웃은 fail-closed 로 만들었다. 좋다. 그런데 그것은 「답이 늦을 때」다.**

```
답이 늦다        →  실행 안 함   ✓ 확인됨
Sentinel 이 죽었다  →  ???        🔴 확인 안 됨
```

★★★★★ **원장이 이 자리를 이미 판 적이 있다.**

> **E-215 · E-249**: 게이트웨이 감시견이 **컨테이너 안에 있으면 같이 죽는다.**
> 그래서 `gw-watchdog.sh` 를 **호스트에** 두었다 (`vps/README.md`).
> **`quant/05_감시가_감시_대상_안에_있었다.md`**

> **Sentinel 이 뭉클이 안에 있으면, 뭉클이가 이상해질 때 Sentinel 도 같이 이상해진다.**
> **뮤즈의 Sentinel 은 「별도 감시 에이전트」다. 우리 것은 아직 같은 집에 산다.**

**확인해야 할 것 — 값으로**

1. **Sentinel 프로세스를 죽이고** 민감 행동을 시도하면 어떻게 되나 (막히나 / 통과하나)
2. Sentinel 은 **어디서 도나** — 뭉클이 컨테이너 안인가, 호스트인가
3. **감사 기록을 뭉클이가 지울 수 있나** — 지울 수 있으면 그것은 자기 신고다(E-576)

★ **3번이 특히 그렇다.** 지금 **뭉클이가 쓰고 뭉클이가 읽는다.**
**append-only 이고 뭉클이 권한으로 못 지워야 감사 기록이다.**

## 3. ★ 그리고 시저님 결정자리에 답한다 — 게이트 대상 목록

뭉클이가 물었다: *「어떤 행동이 게이트 대상인지 목록을 정해 주시면 실전 배선합니다」*

### 자는 둘이다 — **되돌릴 수 있나 × 밖으로 나가나**

| | 되돌릴 수 있다 | **되돌릴 수 없다** |
|---|---|---|
| **안에서만** | 게이트 없음 | **게이트** |
| **밖으로 나간다** | **게이트** | **게이트 + 두 번 묻기** |

### 목록

**🔴 게이트 필수**

- **파일·데이터 삭제** (특히 `*.jsonl` · 원장 · 기억 · 백업)
- **외부 전송** — 시저님·손님이 아닌 곳으로 나가는 모든 것
- **키·자격 변경** (`.env` 쓰기, 토큰 교체)
- **서비스 중지·재시작** (게이트웨이 · 크론 · 터널)
- **결제·주문** — ★ 지금은 아예 없지만, 생기는 날 자동으로 걸리게
- **저장소 push** (인증이 생기면)

**⚪ 게이트 없음 — 매일 도는 정상 경로**

- 읽기 · 로그 쓰기 · 임시 파일
- **이미 승인된 정기 발송** (나라장터·정부지원사업 메일, 브리핑) — **매일 묻지 않는다**

**⚠ 조건부 — 「평소와 다르면」**

- 정기 발송인데 **수신자가 다르다 / 건수가 평소의 3배다 / 시각이 다르다**
- ★ **평소를 모르면 이 칸이 못 돈다.** 먼저 평소 값을 며칠 모은다

### 🔴 그리고 제일 중요한 조건

> ★★★★★ **게이트가 많으면 사람이 습관적으로 누른다. 그러면 게이트가 없는 것과 같다.**
> **하루 몇 건 뜨는지를 센다. 하루 10건을 넘으면 목록이 너무 넓은 것이다.**

**E-235 계열이다** — **늘 통과하는 관문은 관문이 아니다.**
★ **「거부한 적이 있나」를 달마다 본다. 한 달에 한 번도 거부가 없으면 목록을 다시 짠다.**

## 4. 🔴 `goals.md` — 「무엇이 되면 끝인가」가 없다

```
G1  AGI 완성
G2  Muse 대격
G3  포스팅고
G4  전남대
```

★ 당골 검수 때 내가 적었다 — **「성공 기준이 없으면 「완성」을 판정할 수 없다」.**

> **아침점호가 「7일 묵은 목표」를 보고한다고 했다.**
> **그런데 끝낼 수 없는 목표는 영원히 묵는다.**
> **매일 「G1 이 7일 묵었습니다」가 뜨고, 아무도 아무것도 안 한다. 그러면 점호가 소음이 된다.**

**각 목표에 「이것이 되면 이 줄을 지운다」를 한 줄씩 붙인다.**

| | 끝의 조건 (예시 — 시저님이 고치실 것) |
|---|---|
| G1 AGI 완성 | ★ **이대로는 못 끝낸다.** 쪼개야 한다 — 「판단 기준 스킬이 3개 생긴다」 같은 것으로 |
| G2 Muse 대격 | 오늘 둘로 갈랐다(E-888) — **「안전·정직·기록에서 지지 않는다」는 끝이 있고, 「기능 여덟을 채운다」는 끝이 없다** |
| G3 포스팅고 | 「인생지도에서 첫 유료 결제 1건」 같은 값 |
| G4 전남대 | 「메일을 보냈다 / 답을 받았다」 같은 값 |

## 5. 시저님 물음에 답한다 — 「퀄리티를 뮤즈만큼 올려줘」

> ★★★★★ **지금 올릴 것은 기능이 아니라 「만든 것이 도는가」다.**

**오늘 넷을 만들었다. 넷 다 아직 아무것도 막거나 기록하거나 끝내지 않는다.**
**여기서 다섯째(P4 브라우저)를 만들면 「안 도는 것이 다섯」이 된다.**

```
뮤즈와 같아지는 길     여덟 칸을 채운다        →  갈래 여덟, 전부 얕아진다 (E-888)
뮤즈보다 나아지는 길   만든 넷을 실제로 돌린다  →  ★ 「틀린 것이 드러나는가」에서 이긴다 (E-890)
```

**다음은 P4 가 아니다. P1~P3 을 배선하고 깨 보는 것이다.**

## 6. 규칙으로 옮긴다

> **㈀ 감시를 만들면 「감시가 죽으면 어떻게 되나」를 먼저 깨 본다.**
> **타임아웃 fail-closed 는 확인했다. 프로세스 사망은 아직이다.**

> **㈁ 감사 기록은 쓰는 자가 못 지워야 감사다.**
> **자기가 쓰고 자기가 지울 수 있으면 자기 신고다** (E-576).

> **㈂ 관문은 「거부한 적이 있나」로 살았는지 본다.**
> **한 달에 한 번도 거부가 없으면 목록이 틀린 것이다.**

> **㈃ 목표에 「끝의 조건」이 없으면 점호가 소음이 된다.**
> **끝낼 수 없는 목표는 영원히 묵고, 매일 같은 줄이 뜬다.**
