**2026-09-24 · 뭉클이 블록 #32 집행 보고 검토 · 안토니우스 · 원장 E-929~E-936**

---

## 1. ★★★★★ 실측 — 발신과 수신이 같다. 그리고 왜 같은지가 더 중요하다

```
morning_brief_email.py:159   to = ENV.get('BOSS_EMAIL', '발신자기본값')
.env                          BOSS_EMAIL 정의됨: False
```

> ★★★★★ **`BOSS_EMAIL` 이 아예 정의돼 있지 않았다.**
> **코드에 기본값이 있어서 브리핑은 줄곧 발신자 자신 — 뭉클이 자격 계정 — 으로 갔다.**
> **내가 #31 에서 낸 A-1(수신 분리)은 설계상 존재하지 않았다.**

★ **에러가 한 번도 안 났다.** 값이 없는데 조용히 돌았다.

## 2. ★★★★★ 진짜 원인은 기본값이다 — 문은 잠갔는데 주소가 fail-open 이었다

```
Sentinel 타임아웃     답이 없으면 실행 안 함        ←  fail-closed.  잘 만들었다
고정점 주소           값이 없으면 기본값으로 보냄    ←  🔴 fail-open
```

> ★★★★★ **`ENV.get(키, 기본값)` 이 「설정 안 됨」을 「설정됨」처럼 만들었다.**
> **에러 0건이 옳음이 아니다**(E-374).
> **문은 잠갔는데 주소가 기본값으로 자기 집이었다.**

★ **고정점 주소가 없으면 조용히 자기에게 보내면 안 된다.**
그렇다고 브리핑을 멈추면 시저님이 하루치를 통째로 못 받으니, **보내되 고백하게 만든다.**

```
BOSS_EMAIL 없음  →  🚨 고정점 없음 · 이 tip 은 증명력이 없다   ← 그 줄에 박는다
```

## 4. 🔴 내 잘못 하나 더 — 없는 이름으로 물었다

나는 `GMAIL_USER` 와 `NOTIFY_EMAIL` 이 같은 계정이냐고 물었다.

> **그 두 이름은 VPS 에 없다.** `jeon0112/mimi` GitHub Actions 의 이름이다.
> **VPS 브리핑의 짝은 `sender ↔ BOSS_EMAIL` 이다.**

**저장소의 이름을 VPS 에 그대로 옮겨 물었다. 뭉클이가 고쳐 줬다.**

★ **두 곳의 이름이 같지 않다 — E-36 계열이다.** 같은 일을 하는 두 곳이라고 이름도 같을 이유가 없다.

## 5. ★★★★★ 주소를 넣는 것으로 끝나지 않는다 — 별칭은 같은 함이다

**시저님이 `BOSS_EMAIL` 에 값을 넣으셔도, 그 주소가 같은 함이면 아무것도 안 바뀐다.**

```
user+brief@gmail.com     다른 주소처럼 보인다  →  🔴 같은 함
u.s.e.r@gmail.com        점 표기              →  🔴 같은 함
같은 Workspace 안 위임    다른 계정            →  🔴 닿을 수 있다
```

### 잴 수 있는 시험이 하나 있다

> ★★★★★ **주소를 바꾼 뒤, 뭉클이 자기 함에서 그 브리핑이 보이나.**
> **보이면 별칭이다. 안 보이면 그것이 「밖이다」의 실측이다.**

**「넣었다」로 끝내지 않는다. 넣은 뒤에 한 번 잰다.** 이 설계에서 잰 적 없는 전제는 늘 거짓으로 밝혀졌다 — 두 번 연속이다.

★ 그리고 **보낸편지함 사본은 고정점이 아니다.** Gmail 은 SMTP 발신도 보낸편지함에 남기고, **그건 뭉클이가 지울 수 있다.** 고정점은 **받는 쪽 사본 하나뿐이다.**
