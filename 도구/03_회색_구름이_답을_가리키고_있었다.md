# 회색 구름이 답을 가리키고 있었다

> 작성 2026-09-18 · 안토니우스
> 시저님 화면 두 장(`인생지도.포스팅고.kr:8870` 오류 · Cloudflare DNS 기록)과 뭉클이 판독 검토
> 근거: 원장 E-591 ~ E-597

---

## 1. ★ 받은 것 — 못 읽는 것을 못 읽는다고 하고 다르게 쟀다

뭉클이 원문:

> *제 눈이 작은 한글을 또 헷갈려서(「일접시트」로 읽히는데 이건 제 오독 가능성 큼),
> **이름은 측정으로 확인했습니다.***

**닷새 전 E-563 은 정반대였다.** 그때는 한글 이름을 못 읽고 **로마자 이름을 지어내 쟀다** —
`postinggo.kr` 을 쳤는데 시저님 것은 `포스팅고.kr` 이었다. **값이 아니라 물음을 지어냈다.**

오늘은 **못 읽는 자리를 못 읽는다고 적고, 눈 대신 질의로 같은 사실을 쟀다.**

> **우회는 권한을 넓히는 것이고, 대체 측정은 같은 사실을 다른 기구로 재는 것이다.**
> 이건 뒤쪽이다. (E-591)

---

## 2. ★ 화면 자체가 DNS 성공의 증거였다

```
인생지도.포스팅고.kr:8870  →  ERR_CONNECTION_TIMED_OUT
```

**이름을 못 풀었으면 `ERR_NAME_NOT_RESOLVED` 가 뜬다.**
**「연결 시간 초과」는 이름이 IP 로 풀린 뒤, 그 IP 에 TCP 를 걸다 답이 없었다는 뜻이다.**

**그러므로 DNS 는 시저님 PC 에서 이미 성공했다.**
뭉클이는 자기 질의로 근거를 댔는데, **이 화면이 더 강하다** —
**검산은 자기와 맞나가 아니라 남과 맞나다**(E-544).

> **실패 화면이 실패만 말하는 것이 아니다.
> 어디까지 갔다가 실패했는지를 말한다.** (E-592)

---

## 3. 🔴 정정 — 노란 배너를 오독했다

뭉클이:

> *내용은 「네임서버가 아직 Cloudflare 로 안 바뀌었다」는 건데, 그건 옛 화면 갱신 전 메시지입니다*

**배너 실제 문구는 이것이다:**

> **프록시는 대부분의 보안 및 성능 기능에 필요합니다**
> 아래 표에서 "편집"을 클릭하여 DNS 레코드를 프록시로 설정하면
> DDoS 보호, 보안 규칙, 캐싱 등 다양한 혜택을 누릴 수 있습니다.

**네임서버 이야기가 한 글자도 없다.**

**「무시해도 된다」는 결론은 맞았다. 그런데 근거가 틀렸다.**
그러면 **다음에 같은 배너를 보면 또 틀린다.**

> **결론이 맞으면 근거를 안 본다 — 이것이 오독이 오래 사는 방식이다.** (E-593)

---

## 4. ★★★★★ 그리고 그 배너가 오늘의 답을 가리키고 있었다

화면 2 의 실측:

| | |
|---|---|
| 도메인 | **이미 Cloudflare 에 올라가 있다** |
| 레코드 | `A` / `145.79.8.136` / **회색 구름 = DNS 전용** |
| TTL | 자동 |

**회색 구름은 「Cloudflare 가 이름만 알려주고 트래픽에는 손대지 않는다」는 뜻이다.**
**주황으로 바꾸면 Cloudflare 가 앞에 선다.**

> **어제 내가 「손이 없다」고 한 그 자리에, 이미 손이 하나 와 있었다.** (E-589 → E-594)

**다만 나는 이것이 실제로 되는지 안 쟀다.**
어제 caddy 로 정확히 같은 실수를 했으므로 — **이번에는 처방이 아니라 「재라」는 물음으로 낸다.**

---

## 5. 두 길 — 둘 다 내 기억이지 실측이 아니다

### ㈀ 프록시 켜기 (회색 → 주황)

Cloudflare 가 앞에 서고 **사람 ↔ Cloudflare 구간에 HTTPS 가 무료로 붙는다.**

**그런데 제약이 셋 있다 (전부 확인 필요):**

- **내 기억으로 Cloudflare 프록시는 일부 포트만 통과시키고 `8870` 은 그 목록에 없다.**
  그러면 **서비스 포트를 옮겨야 한다.**
- 옮긴 포트를 **방화벽에서 열어야 한다** — 인바운드는 여전히 연다
- **Cloudflare ↔ 원서버 구간은 여전히 평문이다** — **반쪽이다**

### ㈁ Cloudflare Tunnel (`cloudflared`)

서버가 **바깥으로 거는 연결**만 쓴다.

- **방화벽 인바운드를 하나도 안 연다**
- **포트 제약이 없다** — 8870 그대로
- **전 구간 암호화** — 반쪽이 아니다
- **뭉클이가 `127.0.0.1:8870` 에 닿는 것을 이미 쟀으므로 붙일 자리는 있다**(E-581)

**㈁ 가 더 낫다. 다만 셋을 재야 한다:**

1. 뭉클이 컨테이너에 설치되나 (호스트 권한 없이)
2. 컨테이너가 재기동돼도 **남나** — 「부르는 자리」의 짝인 **「남는 자리」**(E-572)
3. **토큰을 안전하게 넣을 수 있나** ← 아래

(E-595)

## 6. 🔴 터널 토큰은 키다 — 전달 경로가 먼저다

Cloudflare Tunnel 을 쓰려면 **시저님이 대시보드에서 만든 토큰을 뭉클이에게 넣어야 한다.**

**지금 우리의 전달 경로는 「시저님이 블록을 손으로 옮긴다」 하나뿐이고,
그 길로 토큰을 보내면 토큰이 대화에 남는다.**

기존 규율 그대로 간다.

- `read -s` 로 넣는다 · `grep -c` 로 **있다/없다만** 확인한다 · **값은 출력하지 않는다**
- **저장소에 넣지 않는다** — 이 저장소는 Public 이다

> **이 조건이 안 서면 ㈁ 는 오늘 하지 않는다.
> 급해서 키를 평문으로 옮기는 것은, 평문 HTTP 를 피하려다 더 나쁜 것을 하는 것이다.** (E-596)

---

## 7. 그래도 8826 대조는 여전히 필요하다

**화면 1 은 그 자리를 안 닫는다.**

`ERR_CONNECTION_TIMED_OUT` 은 **「TCP 를 걸었는데 답이 없다」**까지만 말한다.
**㈎ Hostinger 방화벽 인바운드**인지 **㈏ 시저님 망의 아웃바운드 차단**인지는 **가르지 않는다.**

**8870 은 비표준 포트라, 회사망·ISP 가 나가는 쪽에서 막는 경우가 실제로 있다.**

**그리고 이 대조는 프록시·터널을 고르기 전에도 값이 있다** —
**㈏ 라면 방화벽을 열어도 시저님 PC 에서는 여전히 안 열리고,
원인을 잘못 잡은 채 평문만 켜 두게 된다.** (E-597)

# 후기 — 재기 셋이 돌아왔다 (2026-09-18, 같은 날)

> 근거: 원장 E-598 ~ E-603

## ★★★★★ 뭉클이가 설계를 쓰다 말고 자기를 잡았다

원문 그대로다.

```
→ 관리 키 입력창에 토큰을 붙여넣으면 서버에만 저장됨
   ...가 아니라 — 이 경로는 8870 평문 노출 전제라 순서가 뒤집힙니다.
```

**순환이다.**

> **8870 을 안 열려고 터널을 쓰는데, 터널 토큰을 넣으려고 8870 을 열어야 한다.**

**그리고 틀린 설계를 지우지 않고 남긴 채 그 아래에 고친 것을 붙였다.**
**지웠으면 「왜 그 길이 아닌지」가 사라진다.**

**이것은 검산이 아니라 설계 중의 자기 점검이다** — 다 쓰고 검사한 것이 아니라 **쓰는 중에 걸렸다.** (E-598)

## ★ 출처를 URL 로 댔다 — 어제의 정반대

오늘 아침 도구 조사는 **수 넷에 출처가 하나도 없었고 본인이 회수했다**(E-583).
몇 시간 뒤 같은 사람이 **Cloudflare 공식 문서 URL 을 대고 포트 목록을 그대로 옮겼다.**

```
프록시 HTTP :  80, 8080, 8880, 2052, 2082, 2086, 2095
프록시 HTTPS: 443, 2053, 2083, 2087, 2096, 8443
→ 8870 은 목록에 없다
```

**그리고 이 실측이 내 기억을 검증했다.**
나는 *「8870 은 목록에 없다고 기억한다, 확인해라」*로 냈고 — **확인 결과 맞았다.**

> **기억을 처방으로 내지 않고 물음으로 낸 것이 값을 했다.** (E-589 의 교훈이 같은 날 적용됐다)

## 🔴 그런데 절차에 구멍이 셋 있다

### ① 토큰이 셸 히스토리에 통째로 남는다

```bash
printf '%s' '붙여넣은토큰' > /opt/data/.cf_tunnel_token   ← 이건 명령줄이다
```

**`~/.bash_history` 에 토큰 전문이 평문으로 남고, 그 파일은 `chmod 600` 의 보호 밖이다.**

**우리 규율이 정확히 이것을 막는다 — `read -s` 로 넣고 `grep -c` 로 있다/없다만 확인한다.**
뭉클이는 5단계에서 `grep -c` 는 썼는데 **3단계에서 `read -s` 를 빼먹었다. 반만 적용했다.**

**그리고 권한 창이 하나 더 있다.** `>` 로 만들면 파일이 기본 권한으로 먼저 생기고 `chmod 600` 은 그 뒤다.

고친 형태:

```bash
install -m 600 /dev/null /opt/data/.cf_tunnel_token      # 먼저 600 으로 빈 파일
read -rs CF_TOKEN                                        # 화면에도 히스토리에도 안 남는다
printf '%s' "$CF_TOKEN" > /opt/data/.cf_tunnel_token
unset CF_TOKEN
```
(E-600)

### ② 「평소 쓰시는 wayn… 방법」 — 또 흐릿한 것을 흘렸다

2단계에 시저님의 SSH 접속 방법을 **`wayn…` 이라는 잘린 문자열**로 적었다.

**오늘 아침 같은 사람이 「제 눈이 작은 한글을 헷갈려서 측정으로 확인했습니다」라고 썼다**(E-591).
**그 규율이 이 줄에는 안 걸렸다.**

**「시저님이 평소 쓰시는 접속 방법」이라고만 쓰면 될 자리에 기억의 파편을 넣었다.**

**그리고 더 큰 것 — 시저님이 SSH 로 VPS 에 들어가실 수 있는지를 안 쟀다.**
**절차 전체가 그 전제 위에 서 있는데 전제를 안 쟀다.** 못 들어가시면 3단계에서 멈춘다. (E-601)

### ③ 「크론이 감지해서 재기동」 — 되살리는 것과 재는 것이 안 갈라져 있다

**E-513 에서 뭉클이가 세운 30분 생존 확인은 「1회성이고, 죽어 있어도 되살리지 않는다」였다.**
나는 그것을 **「재는 것과 고치는 것을 갈라 둔 것은 맞다」**고 적었다.

**오늘 것은 갈라져 있지 않다 — 감지하면 되살린다.**

> **되살리면 왜 죽었는지가 안 보인다.
> 매일 아침 조용히 되살아나는 터널은 「잘 돌고 있다」와 구별이 안 된다.**

**권한다 — 크론은 재기만 하고 살리지 않는다. 죽었으면 보고한다.** (E-603)

## ★★★★★ 그리고 — 토큰을 아예 안 옮겨도 될 수 있다

`cloudflared` 에는 두 방식이 있다고 **기억한다.**

| | 방식 | 토큰이 손을 타나 |
|---|---|---|
| **㈎** | 대시보드에서 만든 토큰을 서버에 넣는다 | **탄다** (뭉클이 설계) |
| **㈏** | 서버에서 `cloudflared tunnel login` → **URL 이 뜬다** → 브라우저에서 승인 → **인증서가 서버에 저절로 떨어진다** | **안 탄다** |

**㈏ 면 토큰이 채팅에도, 셸 히스토리에도, 어디에도 손으로 안 옮겨진다 —
①과 ②가 동시에 사라진다.**
그 URL 은 **Cloudflare 로그인을 요구하므로 계정 없이는 못 쓴다.**

**다만 이것은 내 기억이다.**
**어제 caddy 로 같은 실수를 했으므로** — `cloudflared tunnel login --help` 로 **재고 나서 고른다.** (E-602)
