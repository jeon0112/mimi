# 회색 구름이 답을 가리키고 있었다

> 작성 2026-09-18 · 안토니우스
> 시저님 화면 두 장(`인생지도.포스팅고.kr:8870` 오류 · Cloudflare DNS 기록)과 뭉클이 판독 검토
> 근거: 원장 E-591 ~ E-597

---

## 1. ★ 받은 것 — 못 읽는 것을 못 읽는다고 하고 다르게 쟀다

뭉클이 원문:

> *제 눈이 작은 한글을 또 헷갈려서(「일접시트」로 읽히는데 이건 제 오독 가능성 큼),
> **이름은 측정으로 확인했습니다.***

**닷새 전 E-563 은 정반대였다.** 그때는 한글 이름을 못 읽고 **로마자 이름을 지어내 쟀다** —
`postinggo.kr` 을 쳤는데 시저님 것은 `포스팅고.kr` 이었다. **값이 아니라 물음을 지어냈다.**

오늘은 **못 읽는 자리를 못 읽는다고 적고, 눈 대신 질의로 같은 사실을 쟀다.**

> **우회는 권한을 넓히는 것이고, 대체 측정은 같은 사실을 다른 기구로 재는 것이다.**
> 이건 뒤쪽이다. (E-591)

---

## 2. ★ 화면 자체가 DNS 성공의 증거였다

```
인생지도.포스팅고.kr:8870  →  ERR_CONNECTION_TIMED_OUT
```

**이름을 못 풀었으면 `ERR_NAME_NOT_RESOLVED` 가 뜬다.**
**「연결 시간 초과」는 이름이 IP 로 풀린 뒤, 그 IP 에 TCP 를 걸다 답이 없었다는 뜻이다.**

**그러므로 DNS 는 시저님 PC 에서 이미 성공했다.**
뭉클이는 자기 질의로 근거를 댔는데, **이 화면이 더 강하다** —
**검산은 자기와 맞나가 아니라 남과 맞나다**(E-544).

> **실패 화면이 실패만 말하는 것이 아니다.
> 어디까지 갔다가 실패했는지를 말한다.** (E-592)

---

## 3. 🔴 정정 — 노란 배너를 오독했다

뭉클이:

> *내용은 「네임서버가 아직 Cloudflare 로 안 바뀌었다」는 건데, 그건 옛 화면 갱신 전 메시지입니다*

**배너 실제 문구는 이것이다:**

> **프록시는 대부분의 보안 및 성능 기능에 필요합니다**
> 아래 표에서 "편집"을 클릭하여 DNS 레코드를 프록시로 설정하면
> DDoS 보호, 보안 규칙, 캐싱 등 다양한 혜택을 누릴 수 있습니다.

**네임서버 이야기가 한 글자도 없다.**

**「무시해도 된다」는 결론은 맞았다. 그런데 근거가 틀렸다.**
그러면 **다음에 같은 배너를 보면 또 틀린다.**

> **결론이 맞으면 근거를 안 본다 — 이것이 오독이 오래 사는 방식이다.** (E-593)

---

## 4. ★★★★★ 그리고 그 배너가 오늘의 답을 가리키고 있었다

화면 2 의 실측:

| | |
|---|---|
| 도메인 | **이미 Cloudflare 에 올라가 있다** |
| 레코드 | `A` / `145.79.8.136` / **회색 구름 = DNS 전용** |
| TTL | 자동 |

**회색 구름은 「Cloudflare 가 이름만 알려주고 트래픽에는 손대지 않는다」는 뜻이다.**
**주황으로 바꾸면 Cloudflare 가 앞에 선다.**

> **어제 내가 「손이 없다」고 한 그 자리에, 이미 손이 하나 와 있었다.** (E-589 → E-594)

**다만 나는 이것이 실제로 되는지 안 쟀다.**
어제 caddy 로 정확히 같은 실수를 했으므로 — **이번에는 처방이 아니라 「재라」는 물음으로 낸다.**

---

## 5. 두 길 — 둘 다 내 기억이지 실측이 아니다

### ㈀ 프록시 켜기 (회색 → 주황)

Cloudflare 가 앞에 서고 **사람 ↔ Cloudflare 구간에 HTTPS 가 무료로 붙는다.**

**그런데 제약이 셋 있다 (전부 확인 필요):**

- **내 기억으로 Cloudflare 프록시는 일부 포트만 통과시키고 `8870` 은 그 목록에 없다.**
  그러면 **서비스 포트를 옮겨야 한다.**
- 옮긴 포트를 **방화벽에서 열어야 한다** — 인바운드는 여전히 연다
- **Cloudflare ↔ 원서버 구간은 여전히 평문이다** — **반쪽이다**

### ㈁ Cloudflare Tunnel (`cloudflared`)

서버가 **바깥으로 거는 연결**만 쓴다.

- **방화벽 인바운드를 하나도 안 연다**
- **포트 제약이 없다** — 8870 그대로
- **전 구간 암호화** — 반쪽이 아니다
- **뭉클이가 `127.0.0.1:8870` 에 닿는 것을 이미 쟀으므로 붙일 자리는 있다**(E-581)

**㈁ 가 더 낫다. 다만 셋을 재야 한다:**

1. 뭉클이 컨테이너에 설치되나 (호스트 권한 없이)
2. 컨테이너가 재기동돼도 **남나** — 「부르는 자리」의 짝인 **「남는 자리」**(E-572)
3. **토큰을 안전하게 넣을 수 있나** ← 아래

(E-595)

## 6. 🔴 터널 토큰은 키다 — 전달 경로가 먼저다

Cloudflare Tunnel 을 쓰려면 **시저님이 대시보드에서 만든 토큰을 뭉클이에게 넣어야 한다.**

**지금 우리의 전달 경로는 「시저님이 블록을 손으로 옮긴다」 하나뿐이고,
그 길로 토큰을 보내면 토큰이 대화에 남는다.**

기존 규율 그대로 간다.

- `read -s` 로 넣는다 · `grep -c` 로 **있다/없다만** 확인한다 · **값은 출력하지 않는다**
- **저장소에 넣지 않는다** — 이 저장소는 Public 이다

> **이 조건이 안 서면 ㈁ 는 오늘 하지 않는다.
> 급해서 키를 평문으로 옮기는 것은, 평문 HTTP 를 피하려다 더 나쁜 것을 하는 것이다.** (E-596)

---

## 7. 그래도 8826 대조는 여전히 필요하다

**화면 1 은 그 자리를 안 닫는다.**

`ERR_CONNECTION_TIMED_OUT` 은 **「TCP 를 걸었는데 답이 없다」**까지만 말한다.
**㈎ Hostinger 방화벽 인바운드**인지 **㈏ 시저님 망의 아웃바운드 차단**인지는 **가르지 않는다.**

**8870 은 비표준 포트라, 회사망·ISP 가 나가는 쪽에서 막는 경우가 실제로 있다.**

**그리고 이 대조는 프록시·터널을 고르기 전에도 값이 있다** —
**㈏ 라면 방화벽을 열어도 시저님 PC 에서는 여전히 안 열리고,
원인을 잘못 잡은 채 평문만 켜 두게 된다.** (E-597)
