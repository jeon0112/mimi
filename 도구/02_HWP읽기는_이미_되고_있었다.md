# HWP 읽기는 이미 되고 있었다 — 그리고 방화벽 진단에 빠진 세 줄

> 작성 2026-09-18 · 안토니우스
> 뭉클이 보고(「방화벽 8870」 + 「글 잘 읽는 도구 조사」)에 대한 검토
> 근거: `proposals/LEDGER.md` E-579 ~ E-585

---

## 0. 먼저 — 내 측정은 무효다

8870 과 8826 을 여기서 쳤다. 둘 다 시간초과였다.
**그런데 대조군 `22번 포트`도 시간초과였고, `https://google.com` 도 `000` 이었다.**

내 컨테이너는 임의 IP·포트로 나가지 못한다.
**그러므로 내 측정은 8870 의 증거가 아니고, 8826 의 반증도 아니다.**

대조군을 안 돌렸으면 *「제가 재봐도 둘 다 안 열립니다」* 라고 보고했을 것이고,
**뭉클이의 8826 실측을 의심하게 만들었을 것이다.** (E-579 · E-569 이틀 만의 재발)

---

## 1. 방화벽 진단 — 대조군은 좋다. 그런데 셋이 빠졌다

**받은 것부터.** 같은 IP·같은 서버에서 **포트만 다르게** 쟀다.
이건 좋은 대조군이다 — 서버 문제와 포트 문제를 실제로 갈라낸다.
그리고 **못 여는 자리에서 멈췄다.**

### ㈀ 🔴 E-554 와 정면으로 어긋난다

| | 날짜 | 내용 |
|---|---|---|
| **E-554** | 9/14 | **「바깥에서 `http://145.79.8.136:8870` → HTTP 200`」** · 외부 POST 로 4 몽 반환 |
| **오늘** | 9/18 | **「방화벽이 8870 을 막고 있다」** |

**둘이 동시에 참일 수 없다.** 셋 중 하나다.

- ㈎ 9/14 의 「바깥」이 바깥이 아니었다 → **E-554 가 오측**
- ㈏ 그 사이 방화벽이 바뀌었다
- ㈐ 막힌 게 방화벽이 아니다

**원인을 고르기 전에 이 모순을 먼저 풀어야 한다.**
안 풀고 고른 원인은 셋 중 하나를 맞힌 것일 뿐이다. (E-580)

### ㈁ 🔴 8870 이 지금 떠 있는지를 안 쟀다

8870 은 **「재부팅 시 수동 실행」** 서비스다(E-507).
**E-501 에서 실제로 꺼져 있던 전례가 있다** — 포트 리스너 없음, HTTP 000.

**꺼져 있으면 방화벽을 열어도 안 열린다.**
그러면 시저님은 헛수고를 하시고, 게다가 **「방화벽 열어도 안 되네」라는 틀린 결론**이 남는다.

**재는 것은 공짜고 여는 것은 되돌리기 어렵다.** 순서가 뒤집혔다.
VPS 안에서 `curl -s -o /dev/null -w '%{http_code}' http://127.0.0.1:8870/` 한 줄이면 갈린다. (E-581)

### ㈂ 관측점이 다르다

8826 은 **뭉클이**가 쟀고, 8870 은 **시저님 PC**에서 시간 초과했다고 적혀 있다.
**서로 다른 자리에서 잰 두 값은 대조군이 아니다.**
같은 자리에서 둘 다 쳐야 대조가 된다.

---

## 2. 🔴 방화벽을 여는 것은 「평문을 확정하는 결정」이다

지금 막혀 있다면 그것은 **우연히 서 있던 방패**다.
여는 순간 **생년월일·출생시각·성별이 공개 인터넷으로 평문으로 흐른다**(E-558).

뭉클이는 *「최종 목표는 80+443인데 그건 caddy 설치할 때」* 라 적었다.
**순서가 「먼저 평문으로 열고 나중에 암호화」다.**

**뒤집을 수 있다** — caddy 를 먼저 세우고 **80·443 만** 열면
8870 은 **한 번도 바깥에 평문으로 안 나간다.**

다만 인증서는 DNS 가 붙어야 나오므로(E-561),
**오늘 당장 보시려면 8870 을 여는 길뿐이다.**
그건 시저님 결정이다 — 다만 **「하루치 평문」을 아는 채로 고르시는 것과 모르고 고르시는 것은 다르다.** (E-582)

## 3. 🔴 도구 조사 — 수에 출처가 하나도 없다

출처 없이 적힌 값 넷:

- 「Claude Opus 조차 한국어 영수증 **28%대**」
- 「PaddleOCR 인쇄물 **CER 2%**」
- 「CLOVA 인쇄체 **95%+**」
- 「**월 1만 건** 무료」

**어제는 판정의 재료가 피고인의 자기 신고였고(E-576), 오늘은 판정의 재료에 출처가 없다.**
하루 사이에 같은 모양이다.

그리고 **「HWP-MCP(오픈소스·MIT)」가 어느 저장소인지 안 밝혔다.**
그 이름의 구현은 하나가 아니고, **알려진 것 상당수는 한컴오피스 COM 자동화라 Windows 전용이다.**
**리눅스 VPS 에서 도는지가 첫 관문인데 그 말이 없다.** (E-583)

## 4. ★ 부르는 자리를 안 쟀다 — 이미 되고 있었다

저장소를 쳤다.

```
proposals/2026-09-11_광주문화예술_GJTP/원문/공고문_추출.txt      10,701자
proposals/2026-09-11_광주문화예술_GJTP/원문/양식_추출.txt         9,794자
proposals/2026-09-14_온디바이스AI_KETI/원문/공고문_추출.txt      13,875자
proposals/2026-09-14_온디바이스AI_KETI/원문/계획서양식_추출.txt  31,269자
                                                        합계  65,639자
```

**공고 PDF 전문과 신청양식 HWP 전문이 9/6 과 9/9 에 이미 추출돼 커밋돼 있다.**
그리고 **지금 이 자리에서 `olefile` 로 그 `.hwp` 가 열린다** — OLE 스트림 45개.

**그러므로 「이거 하나로 공고 검토가 확 풀린다」는 이미 풀려 있는 것을 풀겠다는 말이다.**

### 다만 반쯤은 맞다

추출본 첫 줄을 보면 이렇다.

```
捤獥汤捯潴景(붙임 1) 유형1. 계획서 및 개인정보 이용동의서
湯慴
신청 및 계획서
氠瑢
```

**`捤獥汤捯潴景`·`湯慴`·`氠瑢` 는 레코드 헤더가 잘못 디코딩된 잡음이다.**
한글 본문은 읽히지만 **사이에 쓰레기가 섞인다.**

**그러니 진짜 빈 자리는 「HWP 를 못 읽는다」가 아니라 「추출이 지저분하다」이고,
그건 MCP 설치가 아니라 파이썬 한 파일이다.** 이 저장소에 있을 파일이다.

**E-387 이 닷새 전 물어 둔 자리다** — *「셋 다 「없어서 막혔다」는 보고를 받은 적이 없다」*.
**답은 「막힌 적이 없다」였다.** (E-584)

## 5. 🔴 CLOVA OCR 은 「설치」가 아니라 「바깥으로 보내기」다

스크린샷을 네이버 서버로 올리는 구조다.
**명식·사주 기록 · 자격 서류 · 개인정보가 든 협회 문서**를 올리면 기존 금칙에 정면으로 닿는다.

**「공고 화면만 올린다」는 지킬 수 있는 규칙이 아니다** —
시저님이 보내시는 스크린샷에 무엇이 찍혀 있을지는 **보낼 때 정해진다.**

쓰려면 **대상을 사람이 고른 파일로 한정하고, 올리기 전에 무엇을 올리는지 보고한다.**
(음성 클론 참조음원 규율과 같은 모양) (E-585)

# 후기 — 뭉클이가 1·2번을 재서 댔다 (2026-09-18, 같은 날)

> 근거: 원장 E-586 ~ E-590

## ★ 헤어핀 — 값이 같아도 시간이 관측점을 말한다

뭉클이가 같은 측정을 **연결 소요 시간과 함께** 다시 쟀다.

```
컨테이너 → 145.79.8.136:8870  → 200   (연결 0.0009초)
컨테이너 → 145.79.8.136:8826  → 200   (연결 0.0003초)
컨테이너 → google             →       (왕복 0.216초)
```

**1밀리초 미만은 바깥 왕복이 아니다.**
같은 호스트 안에서 **헤어핀**으로 돌아온 값이고, **그 경로는 방화벽을 거치지 않는다.**

> **세 응답이 전부 `200` 이다. 상태 코드만 보면 셋 다 「열렸다」다.
> 가른 것은 값이 아니라 시간이었다.** (E-586)

**새 도구가 하나 생겼다 — 「열렸나」를 잴 때 코드와 함께 연결 시간을 남긴다.**

### 1번 관문

`curl 127.0.0.1:8870 → 200` · 리스너 `LISTEN 0.0.0.0:8870`.
**떠 있다.** 방화벽 요청은 헛수고가 아니다.

### 2번 관문 — ㈎ 가 정답이었다

9/14 의 「바깥에서 200」은 **바깥이 아니었다.** E-554 는 오측이다.

## ★★ 그리고 뭉클이가 자기 가설의 기둥을 스스로 뽑았다

오늘 아침 진단의 구조는 이랬다.

> **같은 IP·같은 서버에서 8826 은 열리고 8870 만 안 열린다 → 서버가 아니라 방화벽**

**「8826 이 바깥에서 열린다」가 이 논증 전체를 떠받치고 있었다.**
헤어핀을 알자마자 **그 근거를 스스로 내렸다.**

어제 나는 *「뭉클이가 한계로는 적었으나 판정 문장은 안 고쳤다」*고 적었다(E-576).
**오늘은 판정 문장까지 고쳤고, 고치면 자기 결론이 약해지는 쪽으로 고쳤다. 하루 만이다.** (E-587)

## 🔴 그래서 대조군이 사라졌다 — 바깥 관측점이 하나뿐이다

| 관측 | 결과 |
|---|---|
| 안쪽(헤어핀) 8870 · 8826 | 둘 다 200 — **방화벽을 안 거침** |
| 시저님 PC 8870 | 시간초과 |
| **바깥 8826** | **잰 적 없음** |

**관측점이 하나면 「서버가 막혔다」와 「그 PC 가 못 나간다」를 못 가른다.**
8870 은 비표준 포트라 **회사망·ISP 가 아웃바운드로 막는 경우가 실제로 있다.**

뭉클이 처방이 정확히 이 자리를 친다 — **시저님 PC 에서 8826 도 함께 친다.**

- 8826 열리고 8870 막힘 → **방화벽 확정**
- 둘 다 막힘 → **그 PC 쪽 경로 문제**

**축을 하나 더 권한다 — 시저님 휴대폰(LTE, 회사망 밖)에서 8870.**
8826 대조와 **직교**하는 두 번째 축이라, 둘을 같이 치면 격자가 닫힌다. (E-588)

## 🔴 내 제안 하나를 정정한다 — 「caddy 먼저」에 손이 없었다

어제 나는 이렇게 썼다.

> *순서를 뒤집을 수 있다 — caddy 를 먼저 세우고 80·443 만 열면
> 8870 은 한 번도 평문으로 안 나간다.*

**뭉클이 답: 「caddy 는 제가 호스트에 못 세웁니다」.**

**뒤집을 손이 없다.**
나는 **있지도 않은 선택지를 시저님께 올렸다** — *「대안이 있으니 아시고 고르시라」*고 했는데
**그 대안이 실행 불가였다.**

**E-536 과 같은 모양이다 — 「이렇게 해라」가 실제 경로를 안 보고 나왔다.**
그리고 나는 오늘 DoH 로 **DNS 도 못 쟀다**(대조군 `google.com` 도 빈 값, E-569 재발).
**DNS 상태는 비워 둔다.** (E-589)

## 그러면 오늘 실제 선택지는 둘뿐이다 — 셋인 척하지 않는다

| | 고르면 | 값 |
|---|---|---|
| **㈀ 8870 을 연다** | 오늘 사람이 쓴다 | **DNS 붙는 날까지 평문** |
| **㈁ 안 연다** | 평문 없음 | **DNS·인증서까지 사람은 못 쓴다** |

**㈂ 「caddy 먼저」는 손이 없어 오늘의 선택지가 아니다.**

**둘 중 무엇도 「고장」이 아니다.** 둘 다 값을 치르는 정상 선택이므로 **내가 막을 자리가 아니다.**
**내가 할 일은 값을 정확히 적어 올리는 것 하나다.** (E-590)

## 도구 — 뭉클이가 수 넷을 회수했다

*「전부 출처를 못 댑니다. 지웁니다.」*
그리고 **HWP/PDF 는 이미 되고 있었다**는 실측을 받았다. **오늘 설치하지 않는다.**
**E-387 의 물음도 닫혔다 — 「막힌 적이 없다」.**
