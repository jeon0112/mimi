# 남는 자리가 없으면 잴 수 없다 — 하루에 셋이 나왔다

**2026-09-23 · 뭉클이 블록 #14 집행 보고 분석 · 안토니우스 · 원장 E-743~E-752**

블록 #14 는 두 갈래였다. **B(브리핑 수리)는 완결됐고, A(정답지)는 0단계에서 막혔다.**
그런데 막힌 자리와 고친 자리가 **같은 모양**이었다.

> **셋 다 「부르는 자리는 있는데, 남는 자리가 없다」였다.** (E-491 · E-572)

---

## 1. 셋을 나란히 놓는다

| | 부르는 자리 | 남는 자리 | 그래서 못 재는 것 |
|---|---|---|---|
| ㈀ | Claude API 가 `stop_reason` 을 **준다** | 머니엔진 저장물에 **없다** (`tokens:9620` 만) | **잘렸나** |
| ㈁ | 브리핑 푸터가 `/approve-trade` 를 **매일 안내한다** | 그 **라우트가 없다**. `action=buy/sell` 전용 | **관망을 셌나** |
| ㈂ | `evaluations` 에 「제외」 판정이 **메모리에 있다** | `run_collection.py` 가 **추천·보류만 저장한다** | **제외가 맞았나** |

한 날에 셋이 나온 것은 우연이 아니다. **우리가 「만들었나」만 보고 「남나」를 안 봤다.**

## 2. ㈀ 내가 틀렸다 — `stop_reason` 은 없었다

어제 나는 E-728 에 이렇게 단언했다.

> *「추정할 필요가 없었다 — 값이 이미 있다. 응답에 `stop_reason` 이 함께 온다. **읽기만 하면 된다**」*

뭉클이 실측: **없다.** 전수 키 탐색, `tokens: 9620` 만 존재.

내가 뭘 틀렸나. **「Claude API 가 준다」는 맞다. 「우리 저장물에 남는다」를 확인하지 않았다.**
중간 계층이 토큰 수만 뽑아 저장하고 나머지를 버렸다.

> **API 가 주는 것과 우리 파일에 남는 것은 다른 자리다.** (E-572)

### ★★ 그리고 더 큰 것 — 9/22 도 잘려 있었다

뭉클이가 차선(본문 종결 검사)을 만들어 과거로 돌려보니:

```
0923 잘림:  "...상향 돌파하는 것 — 현재"
0922 잘림:  "...확률을 말할 근거가"
```

**이틀 연속. 둘 다 발송 뒤에만 발견.**

그리고 **9/22 는 아무도 안 잡았다.** 리서치브레인 채점도 9/23 것만 걸렀다.
그러므로 어제 내가 E-727 에 쓴 문장을 고친다.

> ~~잡은 것은 관문이 아니라 채점기였다~~
> → **채점기도 하루치만 잡았다. 전날 것은 그냥 지나갔다.**
> **탐지가 있었던 게 아니라, 운이 하루치 있었다.**

### ★ 뭉클이가 한 것 — 내가 안 시킨 것까지 했다

`verify_me_report.py` — 푸터를 떼고 본문 종결을 검사, `exit 1` 이면 전송 금지.

**양방향 시험을 스스로 걸었다.**

| 시험 | 결과 |
|---|---|
| 0923 (잘린 것) | `exit 1` ✅ |
| 0922 (잘린 것) | `exit 1` ✅ |
| 정상판 | `exit 0` ✅ |

★★★★★ **E-235 음성 대조를 제대로 했다 — 「실패해야 할 때 실패하나」와 「성공해야 할 때 성공하나」 둘 다.**
내 블록은 앞의 것만 시켰다. **정상판을 거는 것은 뭉클이가 스스로 붙였다.**

그리고 **새 관문을 과거 실패 사례로 검증했다.** 미래를 기다리지 않고, 답을 이미 아는 과거로.
이것은 방법으로 남길 값이 있다.

`max_tokens` 는 안 올렸다. **「잘렸다」가 보이는 것이 먼저**라는 순서를 지켰다.

## 3. ㈁ 브리핑이 존재하지 않는 명령을 매일 안내하고 있었다

뭉클이 결론 한 줄: **「안 세어진다」**

```
/approve-trade 라우트 자체가 없다. action=buy/sell 전용.
paper_trades.json 0건.
```

그런데 브리핑 푸터에는 매일 이렇게 적혀 나갔다.

> *"…`/approve-trade` 로 페이퍼 트레이딩 원장에 기록해 검증하십시오"*

> ★★★★★ **시저님이 그것을 치셨으면 아무 일도 일어나지 않았을 것이다. 그리고 조용히.**

E-491 의 가장 순수한 형태다. **부르는 자리(푸터 안내)는 있고 받는 자리가 없다.**

그리고 어제 내가 E-731 에 쓴 「관망 함정」이 **실제로는 더 나빴다.**
나는 「관망이 30건에 세어지나」를 물었는데, 답은 **「세어지고 말고 할 라우트가 없다」**였다.
`buy/sell` 전용이므로 **관망은 아예 입력이 불가능했다. 페이퍼 30건은 영원히 0 이었다.**

뭉클이가 무효선 원장을 신설하고 오늘 5건을 저장했다 — 0923 표 원문 대조.
**9/30 이탈/미이탈 이진 채점.** 관문 6번은 낮추지 않았다. 맞다.

## 4. ★★ ㈂ 가장 큰 것 — 제외는 기록되지 않는다

뭉클이가 덤으로 발견하고, 금칙 경계라 고치지 않고 보고만 했다. **판단이 정확하다.**

`run_collection.py` 71~84행:

```python
for bid in filtered:
    eval_item = next((e for e in evaluations if ...), None)
    if eval_item:
        status = eval_item.get("추천여부", "")
        if status == "추천":   recommended.append(...)
        elif status == "보류": held.append(...)
        # 「제외」는 어느 리스트에도 들어가지 않는다 — 버려진다
```

**판정은 메모리에 있다. 저장만 안 한다.**

### 왜 이것이 정답지 문제보다 큰가

공고 필터가 저지를 수 있는 실수는 둘이고, **값이 전혀 다르다.**

| 실수 | 대가 |
|---|---|
| 거짓 추천 (아닌 걸 추천) | 사람이 한 번 보고 버린다. **시간** |
| **거짓 제외 (될 걸 버림)** | **수의계약 최대 2천만원을 조용히 놓친다** |

> ★★★★★ **비싼 쪽이 기록이 없다.**
> **「추천이 맞았나」는 잴 수 있고 「제외가 맞았나」는 구조적으로 못 잰다.**
> E-235 음성 대조가 **불가능하게 설계돼 있다.**

어제 E-723 에서 「공고 하나 놓치면 2천만원」이라고 썼다.
**그 위험을 재는 자리가 없다는 것을 오늘 알았다.**

## 5. A 가 막힌 것은 막힌 게 아니라 설계대로다 — 그리고 우회로가 필요 없다

뭉클이 0단계 실측:

```
과거 output/*.json → 0 파일
파이프라인 직접 실행 → "NARA_API_KEY가 설정되지 않았습니다" (19키워드 전부), 0건
```

`NARA_API_KEY` 는 **GitHub Secrets 에만** 있다. **저장소가 Public 이라 그것이 규율이다.**
뭉클이가 우회하지 않았다. 맞다.

### ★ 그런데 막히지 않은 길이 있다

**GitHub Actions 는 매일 08:00 KST 에 돌고 있다. 키는 이미 거기 있다.**
VPS 에서 또 돌릴 이유가 없다 — **키를 한 군데 더 두면 관리면만 는다.**

문제는 하나다. **오늘 돌아도 제외 층은 안 남는다.**

> **그러므로 급한 것은 정답지가 아니라 ㈂ 를 고치는 것이다.**
> **오늘 고치면 내일 08:00 실행부터 3층이 다 쌓인다. 안 고치면 내일 것도 없다.**

이것은 시저님의 키도, VPS 도, `gh` 인증도 필요 없다. **저장소 코드 한 곳이다.**

### 정답지의 목적이 바뀌었다

| | |
|---|---|
| 처음 목적 | Sonnet 확신도 보정 → **Jev 를 살지 판정** |
| 그런데 | **Jev 는 이미 멈췄다** (E-723, 1:646) |
| **지금 목적** | **공고 필터가 맞나 — 특히 「제외」가 맞나** |

목적이 바뀌었으니 **순서도 바뀐다. 정답지는 기다려도 되고, 제외 층 저장은 오늘이다.**

## 6. 시저님 결정자리 — 뭉클이가 셋을 냈고, 나는 하나로 줄인다

뭉클이 제안: ① `NARA_API_KEY` 를 VPS 에 ② `gh` 인증 ③ 정답지 보류

**①은 필요 없다** — Actions 가 이미 매일 돈다. 키를 늘리지 않는다.
**③은 「보류」가 아니라 「순서 뒤」다** — 버리는 게 아니다.

남는 것은 **쌓인 결과를 뭉클이에게 어떻게 넘기나** 하나뿐이다.

| 길 | 값 | 걸리는 것 |
|---|---|---|
| ㈀ Actions 가 결과를 저장소에 커밋 → 뭉클이 `git pull` | **0원. 뭉클이는 읽기가 된다** | **저장소가 Public — 우리 판정(무엇을 추천했나)이 공개된다** |
| ㈁ 뭉클이에게 `gh` 읽기 토큰 → 아티팩트 내려받기 | 노출 없음 | 토큰 관리가 는다 |
| ㈂ 시저님이 아티팩트를 받아 중계 | 0원, 노출 없음 | 시저님 손이 간다 |

★ **㈀ 의 걸림돌이 작지 않다.** 공고 자체는 공개 정보지만
**「우리가 무엇을 추천했나」는 전략이다.** 경쟁사가 읽을 수 있다.
**이것은 값으로 정할 수 없고 시저님이 정하신다.**
