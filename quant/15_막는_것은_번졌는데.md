# 막는 것은 번졌는데 고치는 것은 안 번졌다

**2026-09-24 · 뭉클이 머니엔진 연동 보고 분석 · 안토니우스 · 원장 E-850~E-856**

---

## 1. ★★★★★ 먼저 — 관문이 값을 증명했다

```
9/22  잘림 → 아무도 못 잡음 → 발송됨
9/23  잘림 → 채점기가 뒤늦게 → 발송됨
9/24  잘림 ×2 → 관문이 잡음 → ★ 미전송
```

**어제 만든 관문이 오늘 처음으로 나쁜 것을 막았다.**
뭉클이가 *「잘린 채로 보내면 "있다"만 재고 "끝났다"를 못 잰다는 원칙 위반」* 이라고 적었다. **맞다.**

**관문이 없던 이틀은 잘린 글이 나갔고, 있는 오늘은 안 나갔다. 그것이 관문의 값이다.**

---

## 2. 🔴 그런데 좋은 소식이자 나쁜 소식이다

| | |
|---|---|
| 좋은 | 잘린 글이 안 나간다 |
| **나쁜** | **결과가 아예 안 나온다. 4일째다** |

> ★★★★★ **관문은 「막는」 것이지 「고치는」 것이 아니다.**
> **막기만 하면 넷째 날부터는 「아무것도 못 보는 것」이 문제가 된다.**

## 3. ★★★★★ 같은 병을 우리가 이미 풀었다 — 그런데 그 답이 이웃으로 안 갔다

**생의 무늬에서 똑같은 일을 겪었고 원인까지 찾았다.**

> **E-810**: *「지시문을 줘도 재료가 많으면 `length` 다. 재료를 줄이니 `stop` 이다.
> **원인은 입력 총량이었다.**」*
> **E-812**: *「`max_tokens` 를 3000 으로 올려도 재료가 많으면 뚫린다(reasoning 2911).
> **그래서 최종안이 max_tokens 인상이 아니라 축별 분할이 됐다.**」*

**머니엔진도 같은 모양이다.**

```
입력   주식 3종목 + 코인 2종목 = 5종목의 가격·MA·MACD·RSI·거래량·펀딩
출력   국면 판단 + 5종목 분석 + 무효선 + 손익비 + 확률표 + 결론
       → 한 번에 다 쓰라고 한다
```

★★★★★ **답도 같다: 분할.**

```
① 국면 판단        1회
② 종목별          5회 (그 종목 재료만)
③ 종합·무효선     1회
    ★ 잘린 절은 빈 채로 두고, 무엇이 비었는지 적는다
```

**축별 분할과 같은 구조다. 우리가 이미 걸어 본 길이다.**

### ★ 오늘의 문장

> **막는 것(관문)은 생의 무늬에서 머니엔진으로 번졌다.**
> **고치는 것(분할)은 안 번졌다.**

**E-755 와 같은 자리다** — *「고침이 이웃으로 번지지 않았다」*.
**이번에는 우리 자신이 만든 고침이 안 번졌다.**

## 4. ★ 재생성은 답이 아니다 — 값이 그렇게 말한다

```
1차 생성   score 0.688  → 잘림
재생성     score 0.244  → 잘림        ★ 품질이 급락했다
```

> **재생성이 더 나쁜 글을 냈다.**
> **생의 무늬에서 재시도가 들었던 것과 반대다 — 거기는 「축」 단위 재시도였고, 여기는 「통째」 재시도다.**

★★★★★ **통째로 다시 돌리는 것은 같은 벽에 다시 부딪는 일이다.**
**분할이 먼저다. 재시도는 분할 뒤에 절 단위로.**

---

## 5. 🔴 그리고 「전부 버린다」를 고친다

오늘 뭉클이는 **전체를 안 보냈다.** 규율대로다. 그런데 **넷째 날이다.**

**생의 무늬에서 우리가 쓴 규율은 「전부 버린다」가 아니었다.**

> *「`length` 난 축은 **빈 채로 두고**, **버린 문단 수를 적는다**」* (E-812)

**머니엔진에도 같은 규율을 쓴다.**

```
✗  잘렸으니 전체를 버린다              → 넷째 날 아무것도 못 본다
✗  잘린 채로 완성본인 척 보낸다         → 9/22·23 의 그 병
✓  완성된 절까지 보내고, 머리에 적는다
     「🚨 이 보고서는 「시저님께 요청드릴 사항」 절에서 잘렸습니다.
       그 절은 비어 있습니다.」
```

★★★★★ **「지운 것과 없던 것을 구분한다」**(E-31)와 같은 규율이다.
**무엇이 없는지 적으면 부분도 읽을 수 있다. 안 적으면 부분이 거짓말이 된다.**

★ 1차 보고서(score 0.688)의 결론은 **「관망(전 종목, 비중 0%)」** 이었다.
**그 결론까지는 완성됐고, 잘린 것은 그 뒤의 「요청드릴 사항」 절이다.**
**시저님이 오늘 못 보신 것은 잘린 절 하나가 아니라 보고서 전체다.**

## 6. 시저님 승인 요청에 답한다 — 승인. 다만 방향을 좁힌다

뭉클이: *「머니엔진 서버(127.0.0.1:8004) 설정을 조사하겠습니다」*

**승인한다. 그런데 백지에서 조사하지 않는다 — 우리가 이미 아는 답을 먼저 대 본다.**

| 순서 | 무엇 | 왜 |
|---|---|---|
| **0** | **`finish_reason` 과 `reasoning_tokens` 를 먼저 본다** | 생의 무늬에서 이것으로 원인이 갈렸다. **없으면 없다고 적는다** |
| 1 | `max_tokens` 값을 **읽기만** 한다 | 올리지 않는다. **3000 도 뚫린 전례가 있다**(E-812) |
| 2 | **입력 크기를 잰다** — 종목 수 × 지표 수 | 입력 총량이 원인이면 그 수가 근거다 |
| 3 | **분할을 시험한다** — 한 종목만 넣고 1절만 쓰게 | **재료를 줄이면 `stop` 이 나오나.** 생의 무늬에서 이것이 답을 갈랐다 |

★ **0~3 이 끝나기 전에 서버 설정을 고치지 않는다.**
**「올려 보고 안 되면」이 아니라 「원인을 대 보고」다.**
