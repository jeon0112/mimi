# 뭉클이 지시 — 퀀트 데이터 복구

> 2026-09-10 · 안토니우스 작성 · 시저님 결정 반영
>
> **시저님 결정 (2026-09-10)**
> · 페이퍼 트레이딩 시작 조건 — **오늘은 정하지 않는다**
> · 펀딩비 — **지금은 뺀다.** 없는 것을 있는 척하지 않는 게 먼저다

---

## 왜 데이터가 먼저인가

원장이 순서를 말해준다.

| | 무엇 |
|---|---|
| E-26 | `data_fetcher` 를 부르는 크론이 **0개** — 데이터가 안 들어온다 |
| E-24 | 그래서 CSV 가 **10일 묵은 채로** 매일 시황 판단에 쓰였다 |
| E-25 | 펀딩비 null 은 수집 실패가 아니라 **미구현 스텁의 고정 출력** |

**여기서 페이퍼를 먼저 시작하면 안 된다.**
크론이 0개인 채로 시작하면 **10일 묵은 데이터로 400건을 쌓는다.**
그 400건은 무효고, 처음부터 다시 쌓아야 한다.

```
① 데이터가 매일 들어온다        ← 크론
② 묵으면 하류가 못 쓴다          ← is_stale 을 코드로
③ 없는 지표를 지운다             ← 펀딩비 스텁
그다음에 ④ 페이퍼 — 오늘이 아니다
```

---

## 계율

```
한 번에 하나씩. 앞엣것이 확인된 뒤에 뒤엣것을 한다.
크론에 거는 것은 「된다」를 손으로 확인한 뒤에.
```

**안 되는 것을 크론에 걸면 매일 조용히 실패한다.**
그게 E-26 의 거울상이다 — 만들지 않아서 안 도는 것과
만들었는데 조용히 죽어 있는 것은 결과가 같다.

로그는 초록불이고, 우리는 「E-26 을 고쳤다」고 믿었을 것이다.

원장에 **E-39** 로 올렸다. E-01 의 후손이다 —

## is_stale — 네 조사를 받는다

**문 위치** — `money_engine_data_collector.py` 의 `read_csv` 두 곳(61·179행)을
공통 로더 하나로 모은다. 옳다. `graph_write_gate` 와 같은 구조다.

**임계값** — 코인 3일 / 주식 5일. **받는다.** 기존값과 같다는 것도 좋다.
바꿀 이유가 없는 것을 바꾸면 무엇 때문에 달라졌는지 알 수 없게 된다.

**네가 짚은 것이 정확하다** —
*"config 하드코딩 버그가 있는 동안은 어떤 임계값이든 매일 False 로 지나가지 못한다."*
그래서 순서가 **end_date → 데이터 신선 → 크론 → is_stale** 이다.

지금 조용한 플래그(`is_stale: True` 를 dict 에 싣기만)는 **정확히 우리가 아는 그 병**이다 —
호출자가 안 보면 그만이다. 예외로 바꾼다. 다만 **크론이 하루 돈 뒤에.**

## 펀딩비 — ②를 고른다. 다만 오늘은 아니다

네가 하류를 찾아 지우지 않은 것이 옳다. 지웠으면 머니엔진 프롬프트가 요구하는 필드가 사라졌다.

시저님 뜻은 **「없는 것을 있는 척하지 않는다」**였다. 그렇다면 지금이 더 나쁘다 —
크론 프롬프트가 *"바이낸스/바이빗에서 가져오기"* 라고 **요구**하는데
값은 `NOT_IMPLEMENTED` 다. **머니엔진에게 거짓 기대를 심고 있다.**

→ **②** 프롬프트에서 「펀딩 이력」 문구를 빼서 **명시적 미사용**으로 바꾼다.
   페이로드 키는 당분간 그대로 둔다 (깨지지 않게).

**다만 오늘은 하지 않는다.** 그건 머니엔진의 동작을 바꾸는 일이고,
오늘은 데이터 파이프라인 하나만 바꾼다. **한 번에 하나씩.**

그리고 그 전에 확인할 것이 하나 있다 —
**머니엔진이 `NOT_IMPLEMENTED` 라는 문자열을 받아 무엇을 하는가.**
무시하는가, 아니면 그것을 근거처럼 쓰는가. 우리는 아직 모른다.
