# PC 안토니우스 = 실행 팔 — 아키텍처 초안

> 2026-09-25 · 안토니우스 초안 · 뭉클이 확인 필요(뭉클이에게 보낼 블록은 맨 끝)
> 결정: `E-1026`(② 채택) · `E-1028`(PC 뭉클이 대신 PC 안토니우스) · `E-1029`(자본 틀)
> 시저님이 PC 안토니우스에 아직 적응이 안 됐다고 하셔서, **PC 안토니우스가 무엇을 하는지
> 사람이 안 봐도 되게** 설계한다 — 시저님은 매일 브리핑 한 줄만 보면 된다.

## 역할 — 셋이 아니라 계속 둘이다

```
뭉클이(VPS)      —  설계·판단·발견 트리 축적. 지금 하던 것 그대로.
PC 안토니우스     —  ★ 새 임무: 뭉클이의 판단을 받아 "실행"만 한다.
                      스스로 전략을 짜지 않는다. 뭉클이가 짠 것만 실행한다.
안토니우스(이 세션) — 설계·검토. 오늘처럼 계속.
```

★★★ **PC 안토니우스는 넷째 뇌가 아니다.** 판단은 여전히 뭉클이 하나뿐이다.
PC 안토니우스는 **"손"**이다 — 판단은 안 하고 시킨 것만 정확히 한다.
이게 오늘 헌장(`E-1018`)의 원칙과도 맞다 — 판단하는 자와 실행하는 자를 가르면,
실행 쪽이 무엇을 했는지 판단 쪽의 자기 설명 없이도 값으로 확인할 수 있다.

## 하루가 도는 순서

```
① 뭉클이(VPS) — 데이터 보고 전략 신호를 만든다
   ("한국투자증권 API 로 삼성전자 10주 매수" 같은 구체 지시)
   → 파일로 남긴다. 어디에? ↓ "전달 통로" 절 참조

② PC 안토니우스 — 그 파일을 읽는다
   → 지시된 것과 정확히 같은 주문만 넣는다
   → 결과(체결가·수량·시각)를 같은 파일 형식으로 기록

③ 시저님 — 아침 브리핑 한 줄로 본다
   "어제: 삼성전자 10주 매수 · 체결가 71,200 · 자본 잔액 4,850,000(-3.0%)"
```

## 전달 통로 — 손으로 복사하지 않는다

지금 뭉클이 블록(#41·#42)은 **시저님이 복사해서 전달**합니다. 거래 지시까지 그렇게
하면 느리고, 매매 타이밍을 놓치고, **사람이 복사 오류를 낼 수도 있습니다.**

★★★ 제안: **파일 하나가 신호판이다.**

```
뭉클이가 씀   →  /opt/data/trade_signals/오늘날짜.json
                  {"action": "buy", "ticker": "005930", "qty": 10,
                   "reason": "...", "confirm_send": false}
PC 안토니우스가 읽음 → 같은 파일을 (VPS 에서 시저님 PC 로 복사되는 경로 필요 —
                  지금은 git push 로 main 을 거치거나, 시저님이 그 파일을 받아
                  PC 쪽 폴더에 놓는 수동 단계가 남는다. ★ 이 통로 자체가
                  아직 없다 — 뭉클이에게 물어야 할 첫 질문이다)
```

★★★★★ **여기가 이 설계에서 가장 안 풀린 자리다.** VPS(뭉클이)와 PC(안토니우스)는
서로 직접 못 붙는다(`E-1027`, 이 세션도 PC 에 안 닿는다 — 같은 문제). 통로 후보 셋:

| 통로 | 방법 | 위험 |
|---|---|---|
| ① git | 뭉클이가 신호를 `main` 에 커밋 → PC 안토니우스가 pull | ★★★ 뭉클이가 push 자격이 없다(`E-1025`, 오늘 확인됨) — **이 길은 막혀 있다** |
| ② 이메일 | 뭉클이가 신호를 정형 이메일로 시저님/PC 함에 보냄 | 이미 있는 통로(고정점 메일)를 재사용 — ★ 유력 |
| ③ 시저님이 매일 한 번 복사 | 지금 블록처럼 | 느리다. 타이밍 놓치는 전략엔 안 맞는다 |

★★ **오늘은 ②(이메일)를 임시로 제안한다** — 이미 뭉클이가 매일 발신 가능한 메일 경로가
있고(`E-940`), 정형 형식(종목·수량·사유)이면 사람이 안 읽어도 PC 안토니우스가 파싱할 수
있다. **다만 이건 뭉클이가 실제로 할 수 있는지 확인이 필요하다** — 아래 블록에서 묻는다.

## 자본한도 — 시저님 결정 반영 (총 500만원 · 20%)

```
총 투입 자본        5,000,000원
전체 손실 한도(20%)  1,000,000원  ← 여기 닿으면 전면 중단, 시저님께 보고
```

**하위 한도(제안, 뭉클이·시저님 확인 필요):**

| 층 | 한도 | 왜 이 크기인가 |
|---|---|---|
| 1회 거래 | 총자본의 5% (25만원) | 한 번의 판단 실수가 전체 한도의 1/4 이상을 못 먹게 |
| 하루 누적 | 총자본의 10%(50만원) | 하루 안에 한도 절반까지만 — 다음날 다시 볼 여유를 남긴다 |
| 전체(20%, 100만원) | 도달 시 **전면 중단** | `E-1029` 그대로 |

★★★ **중단은 "거래를 막는다"가 아니라 "다음 판단을 사람에게 넘긴다"이다** — 한도에
닿으면 뭉클이는 계속 분석하고 발견 트리는 계속 쌓인다(`E-1015`). 다만 **주문은 PC
안토니우스가 더 안 넣는다.** 이게 오늘 원칙(구조가 막는다, `E-1018`)의 실물이다 —
PC 안토니우스 코드 안에 `누적손실 >= 1,000,000` 이면 주문 함수 자체가 막히게 짠다.

## PC 안토니우스가 지킬 것 (오늘 헌장 E-1018 을 그대로 적용)

- **자기 판단으로 매매하지 않는다** — 뭉클이 신호 파일에 없는 거래는 0건
- **주문 전 confirm_send 요구**(`E-1021`과 같은 구조) — 신호 파일에 `confirm_send: true`가
  명시돼 있어야 주문이 나간다. 사람이 실수로 스크립트를 다시 돌려도 안 나간다
- **매 거래 후 결과를 파일로 남긴다** — 이게 PC 쪽 발견 트리 기록이다
