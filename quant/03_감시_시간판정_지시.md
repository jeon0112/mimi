# 감시를 날짜가 아니라 시간으로 판정한다 — E-50

> 2026-09-10 12:41 UTC · 안토니우스(설계)
> **오늘 밤 21:00 UTC 첫 자율 실행 전까지.** 남은 시간 약 8시간
> 근거 `LEDGER.md` **E-48 · E-49 · E-50**

---

## 1. 무슨 일이 있었나 — 이틀 연속 감시가 틀렸다

**E-48 (어제)** — 감시가 **첫 실전에서 거짓 정상**을 보고했다.
크론 갱신은 실패했는데, 감시가 06:37 **옛 로그의 마지막 줄**(`EXIT=0`)을 읽고 「정상」이라 알렸다.

> **그 줄이 언제 쓰였는지를 안 봤다.**

**E-50 (오늘, 아직 안 터짐)** — E-48 을 고치면서 「로그 마지막 줄이 **오늘(UTC)** 것인가」로 판정하게 했다.
그런데 —

```
크론이 도는 시각   21:00 UTC   (= 06:00 KST)
감시가 보는 시각   다음날 새벽
                   ↑
        날짜가 항상 다르다
```

**정상이어도 매일 `NO_RUN` 오탐이다.**

★ 이게 첫날부터 뜨면 그다음부터 아무도 알림을 안 본다.
  **거짓 경보는 진짜 경보를 죽인다** (E-45 에서 이미 겪었다).

---

## 2. 고치는 원리 — 한 줄

> ## 날짜를 세지 말고 **시간을 재라.**

「오늘인가」가 아니라 **「지금으로부터 몇 시간 전인가」**.

| | 문제 |
|---|---|
| ~~오늘(UTC) 것인가~~ | **자정·시간대 경계에서 매일 깨진다** |
| **26시간 안인가** | 경계가 없다 |

**왜 26인가** — 주기 24 + 여유 2.

| 값 | 왜 안 되나 |
|---|---|
| 24 | 실행이 3분만 늦어도 걸린다. 매번 아슬아슬하다 |
| **26** | **실행 지연을 견디고, 한 번 거르면 잡는다** |
| 48 | 하루를 통째로 놓쳐도 조용하다. 감시가 아니다 |

---

## 3. ★ 무엇을 보는가 — 줄의 **내용**이 아니라 줄의 **시각**

E-48 이 정확히 여기서 났다. `EXIT=0` 은 **어제 것이어도 `EXIT=0`** 이다.

```
1순위 · 로그 줄에 적힌 실행 시각      ← 이것이 진짜
2순위 · 파일 mtime                    ← 보조로만
```

★ **mtime 을 1순위로 쓰지 마라.** mtime 은 다른 이유로도 바뀐다 —
  `touch`, 복사, 로그 회전, 편집기가 건드림.
  **그러면 아무것도 안 돌았는데 mtime 만 새것**이 된다. E-48 의 재발이다.

★ 로그 줄에 시각이 없으면 **그 로그로는 판정할 수 없다.**
  그 경우 먼저 할 일은 감시를 고치는 게 아니라 **로그 줄에 시각을 넣는 것**이다:

```
2026-09-10T21:00:07Z EXIT=0 coin_last=2026-09-10 stock_last=2026-09-09
```

**UTC · ISO8601 · 줄 맨 앞.** 사람이 읽기 좋게가 아니라 **기계가 자르기 좋게.**

## 4. ★★ 판정은 셋이다 — 둘만 보면 E-39 가 돌아온다

```
① 돌았는가      ← 마지막 실행 시각이 26시간 안인가
② 성공했는가    ← EXIT=0 인가
③ 나아갔는가    ← ★ CSV 마지막 날짜가 어제보다 앞으로 갔는가
```

**③이 없으면 「성공적으로 아무것도 안 한다」를 못 잡는다.**

E-39 가 정확히 그거였다 — 매일 `EXIT=0` 인데 데이터는 **8/30 에 멈춰 있었다.**
①②만 보는 감시는 그 10일 동안 매일 「정상」이라고 알렸을 것이다.

> **셋 다 통과해야 조용하다. 하나라도 걸리면 경보다.**
> 그리고 경보에는 **셋 중 무엇이 걸렸는지**를 적는다. 「이상」만으로는 못 고친다.

## 5. 시험 — 여섯. **A만 통과하는 것은 시험이 아니다**

E-46·E-47 에서 배운 것 — **쉬운 시험은 통과한다.** 갈림은 어려운 쪽에서만 드러난다.

| | 상황 | 기대 |
|---|---|---|
| **A** | 8시간 전 실행 · `EXIT=0` · 데이터 어제까지 | **조용** |
| **B** | 마지막 실행이 **30시간 전** | **경보** — ① 안 돌았다 |
| **C** | 2시간 전 실행 · **`EXIT≠0`** | **경보** — ② 실패했다 |
| **D ★** | **8시간 전 실행인데 로그 날짜는 「어제」** | **조용** ← **E-50 이 잡히는 곳** |
| **E** | 로그 파일 자체가 **없다** | **경보** — 단 「안 돌았다」가 아니라 **「모른다 · 로그 없음」**으로 |
| **F ★** | 2시간 전 · `EXIT=0` 인데 **CSV 마지막이 그저께** | **경보** — ③ 안 나아갔다 ← **E-39 계열** |

★ **D 와 F 가 이 시험의 전부다.** 나머지는 통과할 게 뻔하다.

### D 를 어떻게 만드나 — 기다리지 마라

실제로 자정을 넘길 수 없다. **가짜 로그를 만들어서 감시 함수만 돌려라.**

```
· 진짜 로그를 복제해 /tmp 에 놓고, 줄 맨 앞 시각만 바꾼다
· 감시 판정 함수에 그 파일 경로를 넣어 결과만 본다
★ 진짜 로그를 고치거나 지우지 마라 — 오늘 밤 실행이 거기에 쓴다
```

**E 의 구별이 중요하다.** 「안 돌았다」와 「모른다」는 다른 사고다.
로그가 없으면 크론이 안 돈 것일 수도, 로그 경로가 틀린 것일 수도 있다.
**둘을 같은 문구로 알리면 엉뚱한 데를 고치게 된다.**

## 7. 내일 아침에 확인할 것 — 미리 적어둔다

**오늘 손으로 시험한 것과 내일 크론이 돌아서 되는 것은 다르다.** E-49 가 그것이었다.

| 볼 것 | 통과 |
|---|---|
| 로그에 21:00 UTC 대 줄이 **새로 생겼는가** | 생겼다 |
| 그 줄의 `EXIT` | `0` |
| `coin_last` · `stock_last` 가 **어제보다 앞으로** 갔는가 | 갔다 |
| 감시 알림이 왔는가 | **안 왔다** ← 정상이면 조용해야 한다 |

★ 마지막 줄이 D 케이스의 실전 판정이다.
  **정상인데 알림이 오면 E-50 이 안 고쳐진 것이다.**

★ 그리고 **알림이 안 온 것**과 **감시가 안 돈 것**은 또 다르다.
  조용한 아침에는 감시가 돌았는지도 함께 본다 — E-48 의 교훈이 그거였다.
