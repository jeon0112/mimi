# 감시를 날짜가 아니라 시간으로 판정한다 — E-50

> 2026-09-10 12:41 UTC · 안토니우스(설계)
> **오늘 밤 21:00 UTC 첫 자율 실행 전까지.** 남은 시간 약 8시간
> 근거 `LEDGER.md` **E-48 · E-49 · E-50**

---

## 1. 무슨 일이 있었나 — 이틀 연속 감시가 틀렸다

**E-48 (어제)** — 감시가 **첫 실전에서 거짓 정상**을 보고했다.
크론 갱신은 실패했는데, 감시가 06:37 **옛 로그의 마지막 줄**(`EXIT=0`)을 읽고 「정상」이라 알렸다.

> **그 줄이 언제 쓰였는지를 안 봤다.**

**E-50 (오늘, 아직 안 터짐)** — E-48 을 고치면서 「로그 마지막 줄이 **오늘(UTC)** 것인가」로 판정하게 했다.
그런데 —

```
크론이 도는 시각   21:00 UTC   (= 06:00 KST)
감시가 보는 시각   다음날 새벽
                   ↑
        날짜가 항상 다르다
```

**정상이어도 매일 `NO_RUN` 오탐이다.**

★ 이게 첫날부터 뜨면 그다음부터 아무도 알림을 안 본다.
  **거짓 경보는 진짜 경보를 죽인다** (E-45 에서 이미 겪었다).

---

## 2. 고치는 원리 — 한 줄

> ## 날짜를 세지 말고 **시간을 재라.**

「오늘인가」가 아니라 **「지금으로부터 몇 시간 전인가」**.

| | 문제 |
|---|---|
| ~~오늘(UTC) 것인가~~ | **자정·시간대 경계에서 매일 깨진다** |
| **26시간 안인가** | 경계가 없다 |

**왜 26인가** — 주기 24 + 여유 2.

| 값 | 왜 안 되나 |
|---|---|
| 24 | 실행이 3분만 늦어도 걸린다. 매번 아슬아슬하다 |
| **26** | **실행 지연을 견디고, 한 번 거르면 잡는다** |
| 48 | 하루를 통째로 놓쳐도 조용하다. 감시가 아니다 |

## 3. ★ 무엇을 보는가 — 줄의 **내용**이 아니라 줄의 **시각**

E-48 이 정확히 여기서 났다. `EXIT=0` 은 **어제 것이어도 `EXIT=0`** 이다.

```
1순위 · 로그 줄에 적힌 실행 시각      ← 이것이 진짜
2순위 · 파일 mtime                    ← 보조로만
```

★ **mtime 을 1순위로 쓰지 마라.** mtime 은 다른 이유로도 바뀐다 —
  `touch`, 복사, 로그 회전, 편집기가 건드림.
  **그러면 아무것도 안 돌았는데 mtime 만 새것**이 된다. E-48 의 재발이다.

★ 로그 줄에 시각이 없으면 **그 로그로는 판정할 수 없다.**
  그 경우 먼저 할 일은 감시를 고치는 게 아니라 **로그 줄에 시각을 넣는 것**이다:

```
2026-09-10T21:00:07Z EXIT=0 coin_last=2026-09-10 stock_last=2026-09-09
```

**UTC · ISO8601 · 줄 맨 앞.** 사람이 읽기 좋게가 아니라 **기계가 자르기 좋게.**

---

## 4. ★★ 판정은 셋이다 — 둘만 보면 E-39 가 돌아온다

```
① 돌았는가      ← 마지막 실행 시각이 26시간 안인가
② 성공했는가    ← EXIT=0 인가
③ 나아갔는가    ← ★ CSV 마지막 날짜가 어제보다 앞으로 갔는가
```

**③이 없으면 「성공적으로 아무것도 안 한다」를 못 잡는다.**

E-39 가 정확히 그거였다 — 매일 `EXIT=0` 인데 데이터는 **8/30 에 멈춰 있었다.**
①②만 보는 감시는 그 10일 동안 매일 「정상」이라고 알렸을 것이다.

> **셋 다 통과해야 조용하다. 하나라도 걸리면 경보다.**
> 그리고 경보에는 **셋 중 무엇이 걸렸는지**를 적는다. 「이상」만으로는 못 고친다.

## 5. 시험 — 여섯. **A만 통과하는 것은 시험이 아니다**

E-46·E-47 에서 배운 것 — **쉬운 시험은 통과한다.** 갈림은 어려운 쪽에서만 드러난다.

| | 상황 | 기대 |
|---|---|---|
| **A** | 8시간 전 실행 · `EXIT=0` · 데이터 어제까지 | **조용** |
| **B** | 마지막 실행이 **30시간 전** | **경보** — ① 안 돌았다 |
| **C** | 2시간 전 실행 · **`EXIT≠0`** | **경보** — ② 실패했다 |
| **D ★** | **8시간 전 실행인데 로그 날짜는 「어제」** | **조용** ← **E-50 이 잡히는 곳** |
| **E** | 로그 파일 자체가 **없다** | **경보** — 단 「안 돌았다」가 아니라 **「모른다 · 로그 없음」**으로 |
| **F ★** | 2시간 전 · `EXIT=0` 인데 **CSV 마지막이 그저께** | **경보** — ③ 안 나아갔다 ← **E-39 계열** |

★ **D 와 F 가 이 시험의 전부다.** 나머지는 통과할 게 뻔하다.

### D 를 어떻게 만드나 — 기다리지 마라

실제로 자정을 넘길 수 없다. **가짜 로그를 만들어서 감시 함수만 돌려라.**

```
· 진짜 로그를 복제해 /tmp 에 놓고, 줄 맨 앞 시각만 바꾼다
· 감시 판정 함수에 그 파일 경로를 넣어 결과만 본다
★ 진짜 로그를 고치거나 지우지 마라 — 오늘 밤 실행이 거기에 쓴다
```

**E 의 구별이 중요하다.** 「안 돌았다」와 「모른다」는 다른 사고다.
로그가 없으면 크론이 안 돈 것일 수도, 로그 경로가 틀린 것일 수도 있다.
**둘을 같은 문구로 알리면 엉뚱한 데를 고치게 된다.**

## 남은 물음 둘 — 오늘 밤 전에

### ① 구형 줄의 시각은 UTC 인가 KST 인가

신형은 `2026-09-10T21:00:07Z` — **`Z` 가 붙어 UTC 임이 줄 안에 있다.**
구형은 `2026-09-10 09:51:12` — **아무 표시가 없다.**

파서가 이걸 UTC 로 읽는데 실제로 **KST 로 쓰인 줄**이라면 —

```
실제 00:51 UTC 의 실행을  →  09:51 UTC 로 읽는다
                              ↑ 9시간 더 새것으로 본다
```

**낡은 것을 새것으로 본다. 거짓 정상 쪽으로 틀린다.** E-48 과 같은 방향이다.

★ **E-05 가 이 집안 병이다** — 「전체 자동화가 UTC 로 해석되어 의도 대비 9시간 지연」.
  이 시스템에서 시간대 혼동은 **이미 한 번 크게 났다.**

오늘 밤 21:00 이후로는 신형만 쌓이니 내일부터는 문제가 아니다.
**문제는 오늘 밤 그 사이**다. 지금 감시가 한 번 돌면 구형 줄을 읽는다.

> 확인은 한 줄이면 된다 — **구형 줄을 쓴 `echo` 가 `date` 를 어떻게 불렀나.**

### ② 편집한 스크립트를 돌려보지 않았다

`quant_data_refresh.sh` 의 `echo` 줄을 고쳤는데, **고친 뒤 실행한 적이 없다.**
(진짜 로그 마지막 줄이 여전히 구형인 것이 그 증거다)

★ **E-49 가 정확히 이것이었다** — shebang 한 줄 때문에 크론이 통째로 안 돌았다.
  그때도 「어제 수동 시운전은 성공」했었다. **손으로 된 것과 크론이 도는 것은 다르다.**

지금은 그보다 나쁘다. **손으로도 안 돌려봤다.**

> 최소한 문법 검사는 한다 — `bash -n`.
> 따옴표 하나가 안 닫혔으면 **오늘 밤 실행이 통째로 죽는다.**
> 그리고 그건 감시가 잡는다 — 잡지만, **잡을 일을 안 만드는 게 낫다.**

## 작은 것 하나 — 경보 문구의 `or`

F 케이스 실제 출력이 이랬다 —

```
STALE(coin=2026-09-08<2026-09-10 or stock=2026-09-07<2026-09-08)
```

**`or` 때문에 어느 쪽이 걸렸는지가 흐려진다.** 둘 다인지 하나인지 알 수 없다.

> 「이상」만으로는 못 고친다고 했던 것의 한 겹 더 안쪽이다.
> **③이 걸렸다까지는 왔는데, ③의 어느 쪽인지에서 다시 뭉갠다.**

`coin=STALE(2026-09-08<2026-09-10) · stock=OK` 처럼 **각각의 상태를 나란히** 적으면 된다.

★ 급하지 않다. **오늘 밤 실행 뒤에 고친다.** 지금 7케이스 통과한 코드를 건드릴 이유가 없다.

# 2026-09-11 아침 — **감시는 조용했고 엔진은 결손을 말했다**

> 첫 실전 아침이다. §7 확인표의 답이 **아직 안 왔다.**
> 대신 다른 데서 신호가 하나 왔다. 그게 더 중요하다.

## 1. 오늘 아침 받은 것 셋 — 그중 감시는 없다

★ 크론 보고가 왔다고 **감시가 돌았다는 뜻이 아니다.** 이건 다른 잡이다.

## 2. ★★ 07:03 제안서가 스스로 밝힌 것

**엔진이 자기 입으로 결손을 말했다.**

| | |
|---|---|
| 9/10 | **목요일 — 거래일** |

**그런데 없다.**

③의 주식 기준선을 **`stock = 3일 이내`** 로 잡았다. **주말을 견디려고 느슨하게 잡은 것**이다.

## 2. E-61 — **같은 자리에서 두 번째다**

| | 언제 | 무엇을 넣었나 | 결과 |
|---|---|---|---|

## 4. ★★ E-63 — 감시가 못 본 이유. 이게 제일 중요하다

**감시는 속지 않았다. 정확하게 작동했다.** 09:51 실행은 실존했고 그 판정은 옳았다.

문제는 **무엇을 재는가**다.

```
지금 재는 것 :  마지막 「성공」이 몇 시간 전인가        ← 26시간 창
안 재는 것   :  이번 차례의 「시도」가 어떻게 됐나
```

**마지막 성공이 11시간 전이면, 그 뒤에 실패가 백 번 나도 감시는 조용하다.**

그리고 **실패는 로그에 줄을 안 남긴다** — 스크립트가 아예 안 떴으니까.
로그만 보는 감시에게 **「안 떴다」와 「아직 돌 시간이 아니다」는 똑같이 「새 줄 없음」**이다.

> **감시의 눈은 스크립트가 스스로 쓴 것뿐이다. 스크립트가 안 돌면 감시는 눈이 없다.**

### E-50 을 고친 것은 옳았다. 그러나 절반이었다

| | 무엇을 고쳤나 | 무엇이 남았나 |
|---|---|---|
| E-50 | 「오늘(UTC)인가」 → **「26시간 안인가」** | 날짜 경계 오탐이 없어졌다 ✅ |
| **E-63** | | ★ **「이번 차례에 돌았나」는 여전히 못 본다** |

**시간을 재는 것만으로는 차례를 못 본다.** 차례를 보려면 **예정 시각**을 알아야 한다.

### 그래서 판정 ④ — 설계만 적는다. 오늘 만들지 않는다

> ## ④ **직전 예정 시각(21:00 UTC) 이후에 시도의 흔적이 있는가.**

| 지금 | 새로 |
|---|---|
| 26시간 창 — **「언젠가 돌았다」** | ④ — **「이번 차례에 돌았다」** |
| 느슨해서 방금 실패를 삼킨다 | 예정 시각 하나만 알면 된다 |

흔적을 볼 자리는 둘이다. **둘 다 로그 밖이다.**

| 볼 곳 | 무엇이 보이나 | 믿을 수 있나 |
|---|---|---|
| 잡 출력 파일 `cron/output/<job>/*.md` | `Script Error` · `Script not found` 원문 | ✅ **이번에 여기만 진실을 말했다** |
| `executions.db` | `completed` | ❌ **E-62 — 거짓이다** |

★ 더 싼 길이 하나 더 있다 — **스크립트가 시작할 때도 줄을 쓰게 한다.**

```
2026-09-10T21:00:00Z START
2026-09-10T21:00:07Z EXIT=0 coin_last=... stock_last=...
```

`START` 만 있고 `EXIT` 이 없으면 **중간에 죽었다.**
그런데 **이번 경우는 `START` 도 안 남는다** — 스크립트가 아예 안 떴으니까.
**그래서 ④는 로그 밖(잡 출력 파일)을 봐야 한다.** `START` 는 그 다음 겹이다.

| | 답 | 근거 |
|---|---|---|
| 구형 줄 시각 | **UTC** | fetcher 로그 `09:51:12,816` 대조 · 그 실행이 09:51 UTC=18:51 KST 수동분 · 스크립트가 `date -u` 로만 씀(11·16행) |
| `bash -n` | **exit=0** | 문법 정상 |

★ 근거를 셋 댔다. 하나로는 못 정할 것을 셋으로 정했다. **이게 옳은 답하는 법이다.**

## 6. 오늘 할 것 — 하나뿐이다

★ 그리고 **증거는 이미 다 확보했다** — 잡 출력 파일 · 대장 행 · CSV 결손 전부 남아 있다.

| | |

★ **그러니 오늘 밤 경보가 오면 그건 오탐이 아니다.** 그 자리에서 봐야 한다.

## 8. 여기서 배운 것 — 족보에 새 줄

> **실패가 로그에 줄을 못 남기면 감시는 그 실패를 볼 눈이 없다.**

침묵 실패 족보에 더한다. 기존 여섯과 다르다 —

| 기존 | 이번 |
|---|---|
| 성공적으로 아무것도 안 한다 | **아예 안 했는데 대장은 했다고 한다** |
| 감시가 속았다 | **감시는 안 속았다. 볼 자리에 증거가 없었다** |

★ 그리고 하나 더 —

> **「고쳤다」와 「고친 것이 도는 자리에서 돈다」는 다르다.**
