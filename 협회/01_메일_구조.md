# 메일 구조 — 검토 → 사항 보고 → 답변 초안

> 2026-09-09 · 시저님 지목 *"이게 중요해. 이걸 구조로 만들어야 해"*
> 상위 문서 `협회/00_사무국_설계.md`

---

## 1. 순서를 뒤집는다 ★

시저님은 **「답변 문서와 사항을 보고」**라고 하셨다.
설계에서는 **사항이 먼저고 답변이 나중**이다.

| | 틀렸을 때 | 복구 |
|---|---|---|
| 답변 초안이 어설프다 | 사람이 고쳐 쓴다 | **된다** |
| **메일을 놓쳤다** | 기한이 지났다 | **안 된다** |

사무국에서 진짜 사고는 「잘못 답한 것」이 아니라 **「기한을 놓친 것」**이다.
공모 마감 · 제출 기한 · 회신 기한.

> **1순위 산출물은 답변 초안이 아니라 「기한이 걸린 것 목록」이다.**

---

## 2. 이미 우리가 가진 것을 쓴다

메일 검토는 새 문제가 아니다. **`gov_ai_filter.py` 가 이미 푸는 문제**다.
공고를 메일로 바꾼 것뿐이다. 규칙을 그대로 가져온다.

| 크롤러 규칙 | 메일에 그대로 |
|---|---|
| 마감일 못 읽으면 **빈 값 — 지어내지 않는다** | 기한 못 읽으면 비운다 |
| **`D-DAY is None` 은 남긴다** — 모르는 것은 버릴 근거가 아니다 | 기한 미상 메일을 버리지 않는다 |
| 등록일만 보면 「열흘 전에 뜬 내일 마감」을 버린다 | **받은 날짜만 보지 않는다.** 기한도 함께 본다 |
| 결과는 D-day 오름차순, 미상은 뒤로 | 같다 |
| **0건은 「없다」와 「죽었다」를 덮는다** → 실패는 🚨 로 맨 위, `exit(1)` | 같다 |

**바퀴를 다시 만들지 않는다.** 이 규칙들은 실제 사고를 겪고 나온 것이다
(2026-08~09 에 잘못된 주소로 43회 전부 0건을 보내면서 워크플로는 초록불이었다).

## 3. 하루 한 번, 이 순서로

```
① 읽는다        읽기만. 답장하지 않는다. 읽음 표시를 바꾸지 않는다
② 분류한다      A / B / C / D 네 갈래
③ 보고한다      ← 산출물 1  (여기까지가 0단계)
④ 초안을 쓴다    ← 산출물 2  (1단계에서 추가)
⑤ 사람이 보낸다  발송은 언제나 사람
```

**①에서 읽음 표시를 바꾸지 않는 이유** — 직원분이 「누가 벌써 봤네」라고 착각한다.
뭉클이가 읽은 것과 사람이 읽은 것은 다르다.

### 네 갈래

| | 무엇 | 처리 |
|---|---|---|
| **A** | **기한이 있고 우리가 뭔가 해야 함** | 최우선. 놓치면 사고 |
| **B** | 답장이 필요함 (기한 없음) | 초안 대상 |
| **C** | 읽어두면 되는 것 (공지·안내) | 한 줄 요약 |
| **D** | 무관 · 광고 | 버림. **단, 목록은 보여준다** |

**판단이 애매하면 A 로 올린다.** 모르는 것은 버릴 근거가 아니다.

---

## 4. 보고서 형식

```
■ 🚨 못 읽은 것              ← 맨 위. 0건이어도 「0건」이라 적는다
■ A. 기한이 걸린 것          ← D-day 오름차순 / 기한 미상은 맨 뒤 (버리지 않는다)
■ B. 답장이 필요한 것
■ C. 알아두면 되는 것         ← 한 줄씩
■ D. 버린 것                 ← 제목과 건수만
```

### 왜 D 를 보여주는가 ★

**조용히 버리면 침묵 실패다.**
잘못 버렸는지는 버린 쪽이 아니라 **사람이** 봐야 안다.
제목 한 줄이면 훑는 데 3초다. 그 3초가 놓친 공문 하나를 건진다.

### A 항목 한 건의 모양

```
[A-1]  D-3  ·  2026-09-12(금) 18:00 마감
  보낸 곳   ○○재단
  요구       참가 신청서 + 사업자등록증 제출
  근거       본문 3문단 "9월 12일 18시까지"   ← 어디서 읽었는지 밝힌다
  미확인     제출처 주소가 본문에 없음        ← 지어내지 않는다
```

**「근거」와 「미확인」이 있어야 A 항목이다.**
기한을 어디서 읽었는지 못 밝히면 그 기한은 추정이다. 추정이라고 쓴다.

## 5. 답변 초안의 규율 (1단계)

제안서 규율과 같다. `proposals/README.md` 의 절대 규칙이 여기서도 산다.

| 규율 | 뜻 |
|---|---|
| **없는 값은 지어내지 않는다** | 모르는 것은 `■ 사무국 확인 필요: …` 로 남긴다. 채우지 않는다 |
| **약속하지 않는다** | 참석 여부 · 금액 · 기한을 뭉클이가 정하지 않는다. 사람이 정한다 |
| **초안이라고 적는다** | 파일 첫 줄에 「초안 — 발송 전 사무국 확인 필요」 |
| **발송은 사람** | 예외 없다 |

빈칸이 있는 초안은 실패가 아니다. **빈칸을 지어서 채운 초안이 실패다.**

## 6. 단계와 게이트

| 단계 | 뭉클이 | 넘어가는 조건 |
|---|---|---|
| **0. 분류만** | 읽고 A/B/C/D 로 나눠 보고. **초안 없음** | 2주간 **A 를 놓친 것 0건**, D 오분류 0건 |
| **1. 초안** | 답변 초안 작성. **발송 안 함** | 4주간 **오발송 0건**, 사람이 초안을 크게 뜯어고친 비율 하락 |
| **2. 발송** | 정해진 유형만 자동 발송 | 시저님 결정 |

**0단계의 합격 기준이 「A 를 놓치지 않았는가」인 것에 유의한다.**
「분류가 예뻤는가」가 아니다. 놓친 것 하나가 나머지를 다 무효로 만든다.
