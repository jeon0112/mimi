# 8870 기동 — 합격선을 먼저 적는다

2026-09-14 · 안토니우스 · 시저님 결정 「8870 오늘 올리자」

## 1. 기동은 재시작이 아니다

어제 E-494 로 「8870 재시작이 필요하면 뭉클이가 하지 말고 멈추고 보고한다」를 박았다.
오늘 뭉클이가 그대로 섰고, 시저님이 기동을 정하셨다. **금칙이 제 일을 했다.**

그리고 지금 자리는 어제와 다르다.

| | 어제 걱정한 것 | 오늘 하는 것 |
|---|---|---|
| 대상 | 돌고 있는 것을 **재시작** | 안 도는 것을 **기동** |
| 죽일 프로세스 | 있다 | **없다** |
| E-249 구조 | 성립 | **성립하지 않는다** |

**죽일 프로세스가 없으면 「자기를 죽이는 명령을 자기가 실행하는」 일이 안 생긴다.**

다만 **감시견 밖인 것은 그대로다.** 띄운 뒤에 죽으면 여전히 아무도 모른다.
그래서 오늘은 **사람이 본다.**

## 2. ★ 합격선을 먼저 적는다 — 「떴다」와 「제대로 떴다」는 다르다

뭉클이의 게이트 ①(4 몽이 `path: 조합` 으로 나옴)은 **스크립트에서 잰 값**이다.

**그런데 E-491 이 정확히 그 자리였다.**
240판 스크립트에서는 조합 경로가 돌았는데, **화면에는 안 나왔다.**
그래서 여덟 번째 「부르는 것이 있는가」가 열렸던 것이다.

그러므로 오늘의 합격선은 **포트도 HTTP 200 도 아니다.**

| 단계 | 재는 것 | 이것만으로는 |
|---|---|---|
| ㈀ 떴다 | 포트 리스너 있음 · HTTP 200 | **부족** |
| ㈁ 데이터가 붙었다 | 앱이 읽는 `iching_data.json` 이 41괘·키 4개 | **부족** |
| ㈂ **제대로 떴다** | **웹앱 요청**으로 4 몽이 `path: 조합` 으로 나온다 | **합격** |

㈂ 가 서야 **83.3% 가 사람에게 도달한다.** 그 전까지는 여전히 스크립트 안의 수다.

## 3. 기동 명령은 여기 적지 않는다

저장소 전체를 쳤다.

```
$ grep -rn "8870" --include=*.py --include=*.sh --include=*.yml --include=*.md .
→ 내 문서와 원장뿐. 실행 명령·유닛 파일·포트 설정은 한 줄도 없다.
```

원래 「재부팅 시 수동 실행」 서비스라 **VPS 안에만 있다.**
**그래서 블록에 명령을 적지 않았다 — 적으면 그건 내가 지어낸 값이다.**

뭉클이가 제 기록에서 찾아 그대로 쓰고, **못 찾으면 돌리기 전에 멈춘다.**

## 4. 그리고 푸시가 두 번째로 안 됐다

뭉클이가 `5b6b18d` 를 **두 번** 댔다. 두 번 다 쳤고 두 번 다 없었다.

```
$ git cat-file -t 5b6b18d     → fatal: Not a valid object name
$ git ls-remote --heads origin main → 5a0b990   (내 커밋)
saengui/24_붙였다_이중_경로.md        → 없음
```

**같은 sha 를 두 번 댔다는 것은, 뭉클이 쪽에서는 두 번 다 「있다」로 보인다는 뜻이다.**
끊긴 자리가 **뭉클이의 눈에는 안 보인다.**

그래서 보고 형식을 바꾼다.
**「푸시했다」고 쓰지 말고, `git ls-remote --heads origin main` 이 돌려준 sha 를 옮긴다.**
자기 로그가 아니라 **저쪽이 준 답**을 적는 것이다.
