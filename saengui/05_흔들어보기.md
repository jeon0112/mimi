# 흔들어 보기 — 서사가 무엇을 읽고 무엇을 안 읽는가

> 2026-09-09 · **시저님 물음**: *"서사가 무엇을 읽고 무엇을 안 읽는가를 어떻게 확인해 볼까?"*

---

## 두 가지 길

| | 무엇을 하나 | 쓸모 |
|---|---|---|
| ① 코드를 읽는다 | `grep` 으로 어느 함수가 어느 필드를 받나 | **설명**은 된다 |
| ② **흔들어 본다** | **한 재료만 바꿔서 글이 바뀌나 본다** | **판정**이 된다 |

**②가 판정인 이유** — 값이 전달돼도 문장에 영향을 안 줄 수 있다.
받아놓고 안 쓰는 것이다. `grep` 은 그걸 구분하지 못한다.

> 오늘 하루 계속 지킨 규율의 다음 것이다 —
> 「있다」가 아니라 「불린다」를 확인한다.
> **여기서는 「읽는다」를 확인한다. 바꿔보고 달라지는지 본다.**

---

## 자는 이미 있다

`forer_overlap` 을 그대로 쓴다. **쓰임만 다르다.**

| | 무엇을 쟀나 |
|---|---|
| 원래 | 두 **사람**의 리포트가 겹치나 → 개인화 |
| 여기 | 한 **재료**를 바꿨을 때 겹치나 → **민감도** |

```
겹침 100%  →  그 재료를 전혀 안 읽는다
겹침  90%  →  거의 안 읽는다
겹침  40%  →  읽는다
```

**같은 자로 다른 것을 잰다.** 새 도구를 만들지 않는다.

---

## ★ 함정 — 입력을 흔들면 여러 개가 같이 움직인다

생년을 바꾸면 **년주도, 대운도, 오행 분포도** 다 바뀐다.
그러면 리포트가 달라져도 **무엇 때문인지 모른다.**

> **한 번에 하나만 바꾼다** — 우리가 하루 종일 지킨 규율이 여기서도 그대로다.
> 두 개를 같이 바꾸면 어느 쪽이 원인인지 영영 모른다.

**→ 입력을 바꾸지 말고, `compute_saju` 가 낸 dict 를 직접 손대서
   `generate_full_interpretation` 에 넣는다.**

```
saju = compute_saju("1990-01-01", "12:00", "광주", "female")   # 기준
base = generate_full_interpretation(saju, birth_year=1990)

s2 = deepcopy(saju); s2["오행"]["금"] = 5.4                     # 한 칸만
alt = generate_full_interpretation(s2, birth_year=1990)

forer_overlap(base, alt)   # 100% 면 오행을 안 읽는 것이다
```

## 흔들 목록 — 한 번에 하나씩

| # | 흔들 것 | 어떻게 |
|---|---|---|
| 1 | **일간** | 병 → 정 (같은 화, 음양만 바꿈) |
| 2 | **오행 수치** | 금 4.0 → 5.4 (다른 칸은 그대로) |
| 3 | **월주** | 다른 간지로 |
| 4 | **시주** | 다른 간지로 |
| 5 | **년주** | 다른 간지로 |
| 6 | **현재 대운** | 대운 항목만 다른 것으로 |
| 7 | **신강/신약** | 뒤집기 |
| 8 | **주역 괘** | 다른 괘로 |
| 9 | **십성 구성** | 하나 바꾸기 |
| 10 | **성별** | male ↔ female |

★ dict 구조가 위와 다르면 **있는 대로 맞춰 쓰고, 못 흔든 것은 「못 흔듦」이라 적는다.**
  지어내지 않는다.

## 결과는 표 하나다

```
재료          바꿨을 때 겹침    읽는가
─────────────────────────────────────
일간              12%          ✅ 읽는다
오행 수치        100%          ❌ 안 읽는다
현재 대운         95%          ❌ 거의 안 읽는다
월주             100%          ❌
시주             100%          ❌
성별             100%          ❌
괘                88%          △ 조금
```

**이 표 하나가 「무엇을 안 읽는가」의 답이다.**
그리고 **다음 작업의 순서표**이기도 하다 — 100% 인 것부터 읽게 만들면 된다.

---

## 왜 이 방법이 좋은가

| | |
|---|---|
| **코드를 안 읽어도 된다** | 값이 전달돼도 안 쓰이면 100% 로 나온다 |
| **자를 새로 안 만든다** | `forer_overlap` 그대로 |
| **순서표가 함께 나온다** | 100% 인 것이 가장 급한 것 |
| **나중에 다시 잴 수 있다** | 고친 뒤 같은 표를 다시 만들면 나아졌는지 보인다 |

★ 마지막이 중요하다. 이 표는 **한 번 쓰고 버리는 것이 아니라 계기판**이다.
  서사를 고칠 때마다 다시 재면, **정말 나아졌는지**를 주장이 아니라 숫자로 안다.

---

## ①도 함께 한다 — 다만 순서가 있다

**흔들어 보기가 판정이고, 코드 읽기는 설명이다.**

100% 가 나온 재료에 대해서만 `grep` 한다 —
*"이 값은 함수에 전달되기는 하는가, 아예 안 넘어가는가."*

| 전달되나 | 읽나 | 무슨 뜻인가 |
|---|---|---|
| ✅ | ❌ | **받아놓고 안 쓴다** — 문장을 고치면 된다 |
| ❌ | ❌ | **아예 안 넘긴다** — 배선부터 해야 한다 |

**둘은 고치는 방법이 다르다.** 그래서 판정 뒤에 설명이 필요하다.
