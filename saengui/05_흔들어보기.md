# 흔들어 보기 — 서사가 무엇을 읽고 무엇을 안 읽는가

> 2026-09-09 · **시저님 물음**: *"서사가 무엇을 읽고 무엇을 안 읽는가를 어떻게 확인해 볼까?"*

---

## 두 가지 길

| | 무엇을 하나 | 쓸모 |
|---|---|---|
| ① 코드를 읽는다 | `grep` 으로 어느 함수가 어느 필드를 받나 | **설명**은 된다 |
| ② **흔들어 본다** | **한 재료만 바꿔서 글이 바뀌나 본다** | **판정**이 된다 |

**②가 판정인 이유** — 값이 전달돼도 문장에 영향을 안 줄 수 있다.
받아놓고 안 쓰는 것이다. `grep` 은 그걸 구분하지 못한다.

> 오늘 하루 계속 지킨 규율의 다음 것이다 —
> 「있다」가 아니라 「불린다」를 확인한다.
> **여기서는 「읽는다」를 확인한다. 바꿔보고 달라지는지 본다.**

---

## 자는 이미 있다

`forer_overlap` 을 그대로 쓴다. **쓰임만 다르다.**

| | 무엇을 쟀나 |
|---|---|
| 원래 | 두 **사람**의 리포트가 겹치나 → 개인화 |
| 여기 | 한 **재료**를 바꿨을 때 겹치나 → **민감도** |

```
겹침 100%  →  그 재료를 전혀 안 읽는다
겹침  90%  →  거의 안 읽는다
겹침  40%  →  읽는다
```

**같은 자로 다른 것을 잰다.** 새 도구를 만들지 않는다.

---

## ★ 함정 — 입력을 흔들면 여러 개가 같이 움직인다

생년을 바꾸면 **년주도, 대운도, 오행 분포도** 다 바뀐다.
그러면 리포트가 달라져도 **무엇 때문인지 모른다.**

> **한 번에 하나만 바꾼다** — 우리가 하루 종일 지킨 규율이 여기서도 그대로다.
> 두 개를 같이 바꾸면 어느 쪽이 원인인지 영영 모른다.

**→ 입력을 바꾸지 말고, `compute_saju` 가 낸 dict 를 직접 손대서
   `generate_full_interpretation` 에 넣는다.**

```
saju = compute_saju("1990-01-01", "12:00", "광주", "female")   # 기준
base = generate_full_interpretation(saju, birth_year=1990)

s2 = deepcopy(saju); s2["오행"]["금"] = 5.4                     # 한 칸만
alt = generate_full_interpretation(s2, birth_year=1990)

forer_overlap(base, alt)   # 100% 면 오행을 안 읽는 것이다
```

---

## ★★ 0번 — 자를 먼저 검사한다. 흔들기 전에

**아무것도 안 바꾸고 두 번 돌린다.**

```
a = generate_full_interpretation(saju, birth_year=1990)
b = generate_full_interpretation(saju, birth_year=1990)   # 같은 입력
forer_overlap(a, b)      # ★ 100% 여야 한다
```

| 결과 | 뜻 |
|---|---|
| **100%** | 자를 믿을 수 있다. 흔들기로 넘어간다 |
| **100% 미만** | **난수가 섞여 있다.** ★ 여기서 멈춰라 |

★ 100% 가 아니면 **흔들기 결과 전부가 못 믿을 것**이 된다.
  「12% 겹침 → 읽는다」인지 「그냥 매번 다른 글」인지 구분이 안 된다.

> **측정기를 먼저 의심한다** — E-43 · E-45 에서 두 번 배운 것이다.
> 0번을 건너뛰고 1~10번을 다 돌리면, 다 돌리고 나서 처음부터 다시 해야 한다.

---

### ★★ 0번-B — 자가 **맞는 자리를 재는지**도 검사한다 (2026-09-11 추가 · E-57)

0번은 **재현성**만 본다. **입력이 유효한지는 안 본다.** 이 구멍으로 한 번 빠졌다.

```
넣은 값:  '강'          ← 지어낸 값
엔진 값:  '신강' / '신약'  ← 엔진이 실제로 쓰는 어휘
```

엔진은 모르는 값을 받고 **조용히 `else` 로 떨어졌다.** 안 흔든 판이 만들어졌는데
제목 조립이 `"신"+"강"` 으로 라벨만 바꿔서 **「모순」이라는 가장 극적인 모양**으로 나왔다.
0번은 100.0% 로 통과한 뒤였다.

> **자가 흔들리지 않는다는 것과, 자가 맞는 자리를 잰다는 것은 다르다.**

**규칙 — 흔들 값은 지어내지 않는다.**

| 하는 것 | 안 하는 것 |
|---|---|
| 흔들 재료마다 **엔진이 실제로 내놓는 값의 목록**을 코드에서 뽑는다 | 그럴듯한 값을 손으로 적는다 |
| 목록에 없는 값이 들어오면 **그 자리에서 멈춘다** | 조용히 `else` 로 흘려보낸다 |

★ 그리고 **결과가 극적일수록 자를 먼저 의심한다.**
  「모순 발견」은 보고하기 좋은 결과다. 좋은 결과일수록 한 번 더 본다.

## 흔들 목록 — 한 번에 하나씩

| # | 흔들 것 | 어떻게 |
|---|---|---|
| 1 | **일간** | 병 → 정 (같은 화, 음양만 바꿈) |
| 2 | **오행 수치** | 금 4.0 → 5.4 (다른 칸은 그대로) |
| 3 | **월주** | 다른 간지로 |
| 4 | **시주** | 다른 간지로 |
| 5 | **년주** | 다른 간지로 |
| 6 | **현재 대운** | 대운 항목만 다른 것으로 |
| 7 | **신강/신약** | 뒤집기 |
| 8 | **주역 괘** | 다른 괘로 |
| 9 | **십성 구성** | 하나 바꾸기 |
| 10 | **성별** | male ↔ female |

★ dict 구조가 위와 다르면 **있는 대로 맞춰 쓰고, 못 흔든 것은 「못 흔듦」이라 적는다.**
  지어내지 않는다.

---

## ★★ 겹침이 떨어져도 「읽는다」가 아닐 수 있다

`material_citation` 을 만들 때 걸린 함정이 여기서 다시 나온다.

서사가 이렇게 쓰여 있다고 하자 —

```
"당신의 금은 4.0 입니다. 금이 많은 사람은 …"
                ↑ 숫자만 갈아끼운다
```

금을 5.4 로 흔들면 **겹침은 떨어진다.** 그런데 읽은 게 아니다.
**숫자를 베껴 넣었을 뿐 판단이 안 바뀌었다.**

| | 무엇이 바뀌었나 | 판정 |
|---|---|---|
| `금 4.0` → `금 5.4` **만** 바뀜 | 숫자 | ❌ **베껴 넣기** |
| `금이 넉넉하다` → `금이 넘쳐 굳는다` | **결론** | ✅ **읽는다** |

> **겹침은 「달라졌나」를 재지 「읽었나」를 재지 않는다.**

### 그래서 보고에 숫자만 적지 않는다

★ 흔든 뒤 **바뀐 문장 1~2줄을 원문 그대로** 옮겨 적는다.
  숫자만 갈렸는지 판단이 갈렸는지는 **사람이 눈으로 봐야** 안다.

**이건 손이 더 가는 게 아니라, 이 시험의 절반이다.**
숫자만 있는 표는 E-46 을 고쳤다고 말할 근거가 못 된다.

---

## 결과는 표 하나다

```
재료         겹침    판정          바뀐 문장 (원문 1~2줄)
──────────────────────────────────────────────────────────
일간          12%   ✅ 읽는다     "병화는 …" → "정화는 …"
오행 수치    100%   ❌ 안 읽는다   (없음)
현재 대운     95%   ❌ 거의 안 읽음 (없음)
월주         100%   ❌            (없음)
시주         100%   ❌            (없음)
성별         100%   ❌            (없음)
괘            88%   △ 조금        "…" → "…"
십성 구성     31%   ⚠ 숫자만      "정관 2" → "정관 3"   ← ★ 베껴 넣기
```

**이 표 하나가 「무엇을 안 읽는가」의 답이다.**
그리고 **다음 작업의 순서표**이기도 하다 — 100% 인 것부터 읽게 만들면 된다.

---

## 왜 이 방법이 좋은가

| | |
|---|---|
| **코드를 안 읽어도 된다** | 값이 전달돼도 안 쓰이면 100% 로 나온다 |
| **자를 새로 안 만든다** | `forer_overlap` 그대로 |
| **순서표가 함께 나온다** | 100% 인 것이 가장 급한 것 |
| **나중에 다시 잴 수 있다** | 고친 뒤 같은 표를 다시 만들면 나아졌는지 보인다 |

★ 마지막이 중요하다. 이 표는 **한 번 쓰고 버리는 것이 아니라 계기판**이다.
  서사를 고칠 때마다 다시 재면, **정말 나아졌는지**를 주장이 아니라 숫자로 안다.

---

## ①도 함께 한다 — 다만 순서가 있다

**흔들어 보기가 판정이고, 코드 읽기는 설명이다.**

100% 가 나온 재료에 대해서만 `grep` 한다 —
*"이 값은 함수에 전달되기는 하는가, 아예 안 넘어가는가."*

| 전달되나 | 읽나 | 무슨 뜻인가 |
|---|---|---|
| ✅ | ❌ | **받아놓고 안 쓴다** — 문장을 고치면 된다 |
| ❌ | ❌ | **아예 안 넘긴다** — 배선부터 해야 한다 |

**둘은 고치는 방법이 다르다.** 그래서 판정 뒤에 설명이 필요하다.
