## 1. 저장한다면 — 무엇을 저장하는가가 먼저다

입력은 **생년월일시 · 성별**이다. 남의 것이면 개인정보다.

★ 그런데 다행히 **전부 저장할 필요가 없다.**

| | 저장 | 왜 |
|---|---|---|
| 별명 | ✅ | 누구 것인지 알아야 다시 본다 |
| **출생 연도** | ✅ | 대운 계산에 필요하다 (`birth_year=`) |
| **명식 4주** (기사·신축·병인·임오) | ✅ | 결과의 근거 |
| 성별 | ✅ | 대운 순역이 갈린다 |
| 해석 결과 | ✅ | 다시 보기가 목적이다 |
| **생월 · 생일 · 생시** | ❌ **저장하지 않는다** |
| 도시 | ❌ 진태양시 보정에만 쓰인다 |

**왜 월·일·시를 안 남기나** — 명식(간지)은 **생년월일시로 되돌아가지 않는다.**
60갑자는 주기가 있고 시주는 2시간 단위다.
**같은 기능을 유지하면서 식별력만 낮출 수 있다.**

> **필요한 것만 남기면, 새어나가도 덜 새어나간다.**

재계산이 필요하면 그때 다시 입력받는다. 그게 몇 초 더 드는 대신 안전하다.

## 3. ★ 넣는 문만 만들고 빼는 문을 안 만들지 않는다

오늘 이 병을 네 번 봤다 —
E-25(호출 없음) · E-26(조용함) · E-29(치우는 규칙 없음) · E-37(빼는 함수 없음) · E-41(재생성 없음).

**여기서 또 그러면 안 된다.**

기록을 저장하는 순간 **지우는 방법도 같이 만든다.**

| 만들 것 | 왜 |
|---|---|
| **지우기** | 「내 것 지워주세요」에 답할 수 있어야 한다 |
| **목록** | 무엇이 쌓여 있는지 시저님이 볼 수 있어야 한다 |
| 저장 시각 | 언제 것인지 모르면 지울 판단도 못 한다 |

★ **저장 기능과 삭제 기능은 같은 날 만든다.** 나중에 만들면 안 만들어진다.

## 4. 누가 무엇을 보는가

「링크를 아는 사람」이라도 **남의 명식이 보이면 안 된다.**

| | |
|---|---|
| 자기가 넣은 결과 | 본다 |
| 남의 결과 | **안 보인다** |
| 전체 목록 | **시저님만** |

★ 목록 페이지가 누구에게나 열려 있으면 링크 하나로 전부 샌다.
  **가장 흔한 사고다.**

## 5. 화면 — 반나절짜리

엔진이 이미 dict 를 내놓으므로 화면은 얇아도 된다.

```
입력   별명 · 생년월일 · 시간 · 도시 · 성별
  ↓
계산   compute_saju → generate_full_interpretation
  ↓
표시   명식 4주 · 오행 · 일간 · 십성 · 대운 · 괘 · 서사
  ↓
저장   별명 + 연도 + 명식 + 성별 + 결과   (월·일·시는 버린다)
```

**만들지 않을 것** — 회원가입 · 비밀번호 · 결제 · 공유 버튼.
범위가 「가까운 몇 분」이니 그것들이 필요 없다.
**안 만든 것은 고장나지 않는다.**
