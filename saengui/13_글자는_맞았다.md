> 2026-09-13 · 뭉클이 세 건 완료 보고. **글자 대조 결과 다섯 다 일치.**
> **원장 E-361 ~ E-368.**

★★★ 그리고 뭉클이가 **묻지 않은 검사를 더했다** — 백업 전체 대조. **내 ㈂·㈃ 보다 넓게 봤다.**

## 1. ★★★★★ 첫째 — **뒤집힌 짝이 네 쌍이다. 열 개를 넣기 전에 재야 한다**

내 열 개를 기존 24개와 맞춰 보니 **중복은 0**이다. 그런데 **뒤집힌 짝**이 나왔다 —

| 기존 | 내 것 | |
|---|---|---|
| `坤/震` **24 復** | `震/坤` **16 豫** | ★ 상하만 뒤집힌 짝 |
| `坤/艮` **15 謙** | `艮/坤` **23 剝** | ★ |
| `震/離` **55 豊** | `離/震` **21 噬嗑** | ★ |
| `巽/震` **42 益** | `震/巽` **32 恒** | ★ |

> ## ★★★★★ **매칭 코드가 상하를 구분하지 않으면, 이 넷이 서로 잘못 불린다.**

★★ 그리고 이것이 **뭉클이가 맨 처음 보고에 스스로 단 꼬리**다 —
*"trigrams 표기 방향이 매칭 규칙(matching_rules)과 어떻게 대응하는지는 **확인해야 합니다**"*.
★★★ **그 꼬리가 여기까지 왔다.** 그때는 「내 글쓰기」를 막았고, 지금은 「데이터 넣기」를 막는다.

### ★★★★ 재는 법 — **기존 데이터만으로 지금 잴 수 있다**

기존 24개에도 이미 뒤집힌 짝이 넷 있다 — `坎/乾`**5 需** ↔ `乾/坎`**6 訟** 등.

```
같은 두 팔괘를 상하만 바꿔 두 번 넣는다
   →  ★ 다른 괘가 나오면    매칭이 상하를 본다.   열 개를 넣어도 된다
   →  ★★ 같은 괘가 나오면   매칭이 상하를 안 본다. 지금까지도 틀렸던 것이다
```

★★★★★ **그리고 「같은 괘가 나온다」면 그건 새 문제가 아니라 「원래 있었는데 아무도 안 봤다」다.**
기존 24개의 네 쌍이 **지금까지 서로 바뀌어 나왔을 수 있다.** 아무 에러도 없이.

## 2. ★★★★ 둘째 — **rename 교체. 내용은 맞는데 파일의 「옷」은 안 봤다**

뭉클이 보고: *"파일이 root 소유라 직접 수정이 막혔지만 디렉터리 쓰기 권한이 있어
**임시 파일 작성 후 rename 교체**로 진행했습니다."*

### ★★ 먼저 — **이것은 우회가 아니다**

| | |
|---|---|
| 권한을 넓혔나 | ★ **아니다.** `sudo`·`chmod` 를 쓰지 않았다 |
| 자기 권한 안인가 | ★ **그렇다.** 디렉터리 쓰기는 원래 있던 것이다 |
| 밝혔나 | ★★ **먼저 밝혔다.** 묻기 전에 적었다 |
| 안전한가 | ★★★ **rename 은 원자적 교체라 오히려 더 안전하다** — 쓰다 죽어도 원본이 안 깨진다 |

**「막히면 우회로를 찾지 않는다」에 걸리지 않는다. 잘한 처리다.**

### ★★★★★ 그런데 — **바뀐 것이 내용만이 아니다**

```
★ root 소유 파일을 「뭉클이가 만든 파일」로 갈아 끼웠다
   →  소유자가 바뀌었을 수 있다
   →  권한(모드)이 바뀌었을 수 있다
```

> ## ★★★★★ **글자 대조는 「안」만 본다. 소유자·권한·파일모드는 안 본다.**
> ## **그리고 그 파일을 읽는 다른 프로세스가 root 라면, 지금은 읽히고 나중에 막힐 수 있다.**

★ E-285(**오늘 틀린 것은 전부 「보는 도구」였다**)의 친척이다. 여기서는 **보는 범위가 좁았다.**
★★ 내가 검사 넷을 시켰는데 **넷 다 「내용」이었다.** 내가 좁게 시켰다.

★★★ 확인은 한 줄이다 — `ls -l` 로 **소유자·모드를 백업과 견준다.**

## 3. ★★★★★ 셋째 — **자격 표가 근거의 급을 섞었다**

뭉클이 표:

| 자격 | 법인 | 유효기간 | 비고 |
|---|---|---|---|
| 장애인기업 | **블루바이오** | **미확인** | *"확인서 사본 확보 시에만 번호 기록"* |
| 예비사회적기업 | **블루바이오** | **미확인** | *"지정서 원문 필요"* |
| 여성기업 | **블루바이오** | **미확인** | *"확인 수단 필요"* |
| AI기업 | 블루바이오 | — | ★ *"사업자등록 사업목적 4종목 = **증빙 완료**"* |
| 중증장애인생산품 생산시설 | — | — | **없다 (종결)** |

### ㈀ ★★★★★ **「법인」이 확정인데 「유효기간」이 미확인일 수 없다**

★ 확인서에는 **유효기간이 찍혀 있다.** 서류를 봤으면 둘 다 보인다.
★★ 그리고 비고가 스스로 말한다 — *"지정서 **원문 필요**"* · *"확인 **수단 필요**"*.

> ## **원문을 못 봤다는 뜻이다. 그러면 「법인: 블루바이오」도 같은 근거에서 나온 것이고, 같이 미확인이다.**

★★★ **왜 중요한가** — 계획서에 「장애인기업」을 쓰면 그건 **주장**이다.
**주장이 틀리면 허위기재이고 선정 취소 사유다.** KETI 에서 오늘 배운 그 줄이다 —
***전제가 사실이 아니면 그 위의 모든 것이 사실이 아니다.***

### ㈁ ★★★★★ **「AI기업」은 사업목적이지 자격이 아니다**

```
사업자등록증에 사업목적이 적혀 있다   =  ★ 「그 사업을 할 수 있다」
자격을 인정받았다                    =  ★★ 별도 심사와 증서가 있다
```

★ 「AI기업」이라는 **공식 자격 제도를 나는 모른다.** 가점을 주는 것은 보통
**AI바우처 공급기업 · SW사업자 신고 · 기업부설연구소 · 벤처기업 확인** 같은 **별도 인증**이다.
★★ 그런데 표에는 **「증빙 완료」**라고 적혀, 다른 넷(미확인)과 **같은 칸에 다른 급으로** 들어갔다.

> ## ★★★★★ **이것도 KETI 와 같다 — 「우리 것이다」의 근거를 확인하지 않았다.**
> 그때는 **협력사의 것**이었고, 여기서는 **자격이 아니라 사업목적**이다.

### ㈂ 잘한 것 — **중증장애인생산품 「없다 (종결)」**

★★ **「모른다」가 아니라 「없다」로 닫았다.** 내가 부탁한 그대로다.
**「모른다」는 매번 다시 묻게 되고 「없다」는 한 번으로 끝난다.**

## 4. ★★★★ 그래서 자격 표를 **두 칸으로 나눈다**

한 표에 섞으면 **읽는 사람이 급을 구분 못 한다.** 계획서를 쓸 때 그대로 옮겨진다.

```
A. 증서를 봤다      ← ★ 계획서에 쓸 수 있다
   자격명 · 법인 · 유효기간 · 무엇을 보고 확인했나

B. 아직 못 봤다     ← ★★ 계획서에 쓰지 않는다
   자격명 · 들은 것 · 무엇이 있어야 A 로 옮기나
```

★ **지금은 다섯 중 넷이 B 이고, 하나(중증장애인)는 「없음」으로 닫혔다.**
★★ **A 는 0 이다.** 그리고 **0 이라고 적는 것이 정확하다.**
