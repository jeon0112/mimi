# 빈축이 설명하는가 — 「사람을 본다」에 대안 설명이 하나 남았다

**2026-09-23 · 뭉클이 블록 #19 집행 보고 분석 · 안토니우스 · 원장 E-817~E-824**

---

## 1. 값은 깨끗하다

```
같은 사람(1955 남) 3회   A = 0.41 / 0.47 / 0.47   σ_안 = 0.0277
사람 11판                A = 0.18 ~ 0.47          σ_밖 = 0.1017
                                                  비 3.7배
11판 전부 delta 양수 (+0.10 ~ +0.41)
바꿔치기 한 판도 통과 안 함
1970 여 재시도 성공 (빈축 2, A=0.35) — 지난 전축 실패는 추론 산포였다
```

**σ_안 ≪ σ_밖.** 설계한 대로 갈렸고, **11판을 결과를 보지 않고 미리 정했다.**

---

## 2. 🔴 그런데 뭉클이가 스스로 적은 한 줄이 이 판정을 위협한다

> *「덤 관찰: **빈축 수와 A 가 반비례한다**(빈축 4→0.18, 빈축 2→0.24~0.35).
> 축이 빠지면 그 사람의 재료가 글에서 빠진다는 뜻 — **사람을 본다는 판정의 이면이다**」*

★★★★★ **이면이 아니라 대안 설명일 수 있다.**

```
판정 ㉠   A 가 흩어진다  ←  사람이 다르다        (우리가 원하는 것)
판정 ㉢   A 가 흩어진다  ←  빈축 수가 다르다     ★ 아직 안 배제했다
```

**빈축은 생성 실패의 흔적이지 그 사람의 성질이 아니다.**
**만약 σ_밖 0.1017 이 빈축 수로 거의 다 설명되면, 우리가 잰 것은 「사람 차이」가 아니라 「그날 몇 번 실패했나」다.**

### ★ 그리고 σ_안 도 같은 물음을 받는다

같은 사람 3회의 A 가 0.41 / 0.47 / 0.47 로 거의 같았다.

> **그 세 번의 빈축 수가 같았나?**

- **같았다면** — σ_안 이 작은 것은 당연하다. **아무것도 안 잰 것이다**
- **달랐는데도 A 가 비슷했다면** — 빈축은 A 를 크게 흔들지 않는다는 뜻이고, **㉠ 이 강해진다**

**이 한 줄이 판정을 가른다.**

## 3. 가르는 법 — 셋, 쉬운 것부터

| | 어떻게 | 무엇을 말해 주나 |
|---|---|---|
| ① | **빈축 0 인 판만 모아 σ_밖 을 다시 잰다** | 그래도 흩어지면 **㉠ 확정** |
| ② | **A 를 「채워진 축 수」로 나눈다** (축당 인용률) | 빈축 효과를 나눠 없앤다 |
| ③ | 빈축 수와 A 의 상관을 값으로 (r) | 얼마나 설명되는지 크기로 |

★ **①이 제일 깨끗하다.** 다만 빈축 0 인 판이 몇 개인지 모른다 — **세는 것이 먼저다.**
**빈축 0 인 판이 3판 미만이면 ② 로 간다.**

## 4. ★ 그리고 이 관찰 자체가 값이다 — 결정자리 ①의 답

뭉클이가 물었다: **축별 빈축 재시도 규칙(1회 더)을 둘까.**

**둔다. 다만 조건이 둘이다.**

```
1) 몇 번 만에 됐는지를 기록한다  (1회차 성공 / 2회차 성공 / 끝내 빈축)
2) ★ 재시도로 A 가 오르면 그것은 「글이 좋아진 것」이 아니라 「축이 찬 것」이다.
   두 개를 같은 칸에 적지 않는다
```

★★★★★ **재시도를 넣으면 빈축이 줄고 A 가 오른다. 그것을 「개선」으로 읽으면 안 된다.**
**A 가 오른 이유가 둘(글이 재료를 더 씀 / 축이 더 채워짐)인데, 기록이 없으면 구분이 사라진다.**

**그래서 §3 의 측정을 재시도 규칙을 넣기 *전에* 한다.** 지금 값이 기준선이다.

## 5. 결정자리 ② — SMTP 앱 비밀번호를 점검에 넣나

**넣는다.** 메일 발송은 **매일 도는 핵심 경로**다(나라장터·정부지원사업 둘 다).
여기가 죽으면 파이프라인이 다 돌고도 결과가 안 온다 — **E-40 「했다」와 「닿았다」는 다르다.**

**무엇으로 재나 — 또 다른 자다.**

| | |
|---|---|
| 재는 법 | **SMTP 연결 → `AUTH` → `QUIT`.** 메일은 보내지 않는다 |
| 「살았다」 | `AUTH` 가 235 로 통과 |
| 🔴 주의 | **하루 1회만.** 잦은 인증 실패·시도는 Google 이 막는다 |
| 표에 적을 것 | `GMAIL_APP_PASSWORD  235  (SMTP AUTH)` — **측정 방식을 같은 줄에** |

★ **키마다 자가 다르다**는 규율이 이제 넷째 종류를 얻었다 — API 키 · OAuth · 터널 토큰 · **SMTP**.

## 7. 지금 판정을 어떻게 적나

> **「사람을 본다」가 유력하다. σ_안 ≪ σ_밖 (3.7배)이고, 11판 전부 delta 가 양수이며 바꿔치기가 한 판도 통과하지 않았다.**
> **다만 「빈축 수가 A 를 흔든다」는 대안 설명을 아직 배제하지 못했다.**
> **§3 의 측정 뒤에 확정한다.**

★ 어제 나는 n=1 로 굳혔다가 회수했다. **오늘은 n=11 이고 값도 깨끗하지만, 교란 요인이 하나 남았으면 그것을 적는다.**

## 8. 규칙으로 옮긴다

> **㈀ 흩어짐을 찾았으면 「무엇이 흩어지게 했나」를 하나 더 의심한다.**
> **우리가 바란 원인이 아니라 다른 것이 흔들었을 수 있다.**
> **σ 를 두 번 나눠 재기(안/밖)까지 왔으면, 세 번째 칼은 「교란 요인을 고정하고 다시」다.**

> **㈁ 고치면 값이 오르는 손잡이는, 고치기 전에 기준선을 남긴다.**
> **재시도를 넣으면 A 가 오른다 — 그것이 「글이 좋아진 것」인지 「축이 찬 것」인지는 기준선이 있어야 갈린다.**

> **㈂ 자가 종류마다 다르다** (넷째: SMTP).
> **표에 「무엇으로 쟀나」를 같은 줄에 적는다.**
