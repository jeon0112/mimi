## 바뀐 것

**이전** — 한 표에 성격이 다른 것이 섞여 있었다.

```
행동 45% + 맥락 30% + MBTI 20% + 사주 5%
```

**이후** — 표를 둘로 나눴다.

### ① 증거 축 (합 100) — 무엇이 사실인가

| 축 | 비중 | 변화 |
|---|---:|---|
| 행동 — 실제로 한 것·기록한 것 | 40% | 45 → 40 |
| **관계 — 오행 교환(생·극·합·충)** | **25%** | **신설** |
| 맥락 — 지금의 상황·감정·관심 | 25% | 30 → 25 |
| 타고난 지표 — 사주 5 + 손금 5 | 10% | 5 → 10 |

### ② 형식 층 (가중치 없음) — 어떻게 말할 것인가

| 층 | 역할 |
|---|---|
| 주역 64괘 | 리포트의 서사 골격 |
| MBTI | 어휘와 톤 |
| 손금 오버레이 | 물증·개인화 지각(신뢰) |

**MBTI와 주역은 근거가 아니라 말하는 방식이다.** "무엇이 사실인가"에 기여하지 않는 것에
가중치를 주면 비중 싸움이 되고, "주역이 몇 퍼센트 맞았나"라는 답할 수 없는 질문이 생긴다.

형식 층으로 내려간다고 역할이 줄지 않는다. 오히려 커진다 —
주역은 모든 리포트의 뼈대가 되고, MBTI는 모든 문장의 톤이 된다.

## 코드가 스스로 지키는 것

숫자만 옮기면 몇 달 뒤 조용히 되돌아간다. 그래서 판단을 코드에 박았다.

| 장치 | 하는 일 |
|---|---|
| `_validate()` (import 시 실행) | 합이 100이 아니면 **앱이 안 뜬다** |
| `FORBIDDEN_IN_EVIDENCE` | `MBTI`·`주역`·`64괘` 를 증거 축에 넣으면 **터진다** |
| `resolve(available)` | 데이터 없는 축을 재정규화하되 **빠진 축을 함께 돌려준다** |
| `prompt_block()` | 프롬프트에 숫자를 손으로 적지 않게 한다 |
| `cache_key()` | 표를 고치면 캐시가 무효화된다 |

`resolve()`가 빠진 축을 돌려주는 이유: 관계 축은 신설이라 초기 사용자에게 데이터가 없다.
25%를 그냥 없애고 나머지를 늘리면 **왜 그 해석이 나왔는지 나중에 설명할 수 없다.**
빠진 것은 빠졌다고 리포트 근거란에 남긴다.

## 관계 축을 언제 켜는가

`관계` 축(25%)을 채울 `relation_engine.py` 는 아래에 만들었다.
다만 5단계 중 **대운 교차**는 `saju_engine` 의 대운 산출을 `{연도: 오행}` 으로
바꾸는 어댑터가 있어야 돈다. 그 전까지는 `daeun=None` 으로 두고 그 단계를 비운다.

관계 데이터가 아직 없는 사용자에게는 `resolve()` 가 관계 축을 빼고 재정규화하며,
빠졌다는 사실을 함께 돌려준다. **그 상태로 동작하는 것이 맞다.**
없는 축을 있는 척 채우지 않는다.

# 관계 엔진 (`relation_engine.py`)

증거 축 **25%** 를 배정받았지만 코드가 없던 자리를 채운다.

방법론은 새로 만든 게 아니다. `advanced analysis methods` 문서의
**"다인물 관계 심화 — 음양 방향성 분석"** 5단계를 그대로 옮겼다.

| 단계 | 검사 | 산출 |
|---|---|---|
| 1 | 양일간 vs 음일간 | 다르면 `보완적`, 같으면 `경쟁적` |
| 2 | 천간 5합 성립 여부 | 합이면 `천간합`, 극 관계였다면 `극중생합` |
| 3 | 음양 방향성 | 양이 밀고 음이 받는다 — 누가 어느 쪽인가 |
| 4 | 서로에게 어떤 십성인가 | `비대칭` / `대칭` |
| 5 | 대운 교차점 | `결실기있음` + 연도, 대운 없으면 `결실기미상` |

## 이 엔진이 하지 않는 것 — 성격을 말하지 않는다

`behavior_mapper.py` 의 첫 원칙이 여기에도 적용된다.
**"목이 많으면 성장형이다" 같은 직접 매핑은 금지다.**

그래서 출력이 자유 문장이 아니라 **정해진 태그 상수**뿐이다.

```python
TAGS = {"보완적","경쟁적","천간합","극중생합","상생","상극","동기",
        "대칭","비대칭","결실기있음","결실기미상"}
```

목록 밖의 말이 태그에 들어오면 `_assert_tags()` 가 예외를 던진다.
`"리더형"`, `"성장형"` 같은 단정은 코드가 막는다.
구조만 내놓고, 그것이 사람에게 무엇을 뜻하는지는 해석 계층이 맡는다.

## 모르는 것은 모른다고 한다

`Person.daeun` 이 `None` 이면 5단계를 **계산하지 않는다.**
`Step.known=False` 로 표시하고 `missing` 에 남긴다.

`None`(모른다)과 `{}`(대운이 없다)는 다른 상태다. 섞지 않는다.
결실기가 실제로 안 겹치면 `timing=None` 이되 `결실기미상` 태그는 붙지 않는다 —
**"모른다"와 "없다"를 구분한다.**

## 십성 편/정 — 표준으로 확정 (2026-09-06)

`advanced analysis methods` 문서의 사례가 표준과 어긋나 있었다.
**시저님 결정: 문서를 고치고 표준으로 간다.**

| | 원문 | 표준 (확정) |
|---|---|---|
| 己(음토) → 甲(양목) | ~~편관~~ | **정관** |
| 甲(양목) → 己(음토) | ~~편재~~ | **정재** |

규칙은 **음양이 같으면 편(偏), 다르면 정(正)** 이다. 己는 음, 甲은 양이라 둘 다 정(正)이다.

전체 10×10 표와 정정 경위는 **[`십성표.md`](십성표.md)** 에 있다.
그 표는 손으로 적은 게 아니라 `ten_god()` 이 산출한 값을 생성해 붙인 것이라
**코드와 문서가 갈릴 수 없다.**

### 남은 일 — 원본 문서와 기억을 고쳐야 한다

이 저장소만 고치면 원본이 그대로 남아 다시 들어온다.
- `advanced analysis methods` 원본의 해당 줄
- 뭉클이 메모리에 저장된 사례
둘 다 정정해야 끝난다. (뭉클이 작업)

# 손금 (`palm_features.py`)

**이 파일은 사진을 보지 않는다.** CV 파이프라인이 만든 값을 받아
LLM 에게 넘겨도 되는 형태인지 판정하고, 넘길 형태로 바꾼다.

설계 근거는 Model Council(GPT-5.6 Sol × Claude Opus 5) 합의문이다.
두 모델이 **서로 다른 논리 경로로 같은 결론에 도달한 지점**이 골격이다.

> CV(측정) 계층과 LLM(서사) 계층을 물리적으로 분리하고,
> 그 사이를 **수치 JSON 하나로만** 잇는다.
> 멀티모달 LLM 에 손 사진을 그대로 던지는 "쉬운 길"은 두 모델 모두 반대했다.

## ① 연속값을 LLM 에 넘기지 않는다 — 밴드로만

길이 187.3px 과 188.1px 은 **같은 손의 두 장에서 흔히 나온다.**
그대로 넘기면 문장이 흔들리고, 사용자는 다른 운세를 본다.

```
길이   짧음 / 보통 / 김
곡선   직선형 / 완만 / 깊은곡선
선명도 옅음 / 보통 / 뚜렷        ← depth 아님. depth_proxy 다
```

`reading_key()` 는 **밴드만으로** 만든다. `confidence` 도 넣지 않는다 —
같은 손인데 조명이 조금 달랐을 뿐이다.

**결정론은 캐시로 덧칠하는 게 아니라 계약에서 확보한다.**

## ② 신뢰도가 미달이면 해석을 만들지 않는다

```
MIN_LINE_CONFIDENCE = 0.60
MIN_IMAGE_QUALITY   = 0.60
```

거절 사유는 셋이다 — 손등 촬영 / 사진 품질 / 주선 신뢰도.
**거절할 때는 무엇을 하면 되는지 함께 준다.**
"분석할 수 없습니다"만 주는 거절은 거절이 아니라 방치다.

```
사유: 손등이 찍혔다 / 사진 품질이 기준 미달 (0.41 < 0.6)
안내: 손바닥이 보이도록 손을 뒤집어 다시 찍어주세요 / 초점이 흐립니다
```

거절된 측정값으로는 `to_prompt_block()` 이 아예 실행되지 않는다.
문이 하나뿐이라 우회로가 없다.

## ③ 이름을 정직하게 짓는다

`depth` 가 아니라 **`depth_proxy`** 다. 실제 3D 깊이를 잰 적이 없다.
계약의 정직성이 이후 해석과 마케팅의 과장을 막는다.

## 코드가 스스로 지키는 것

| 장치 | 하는 일 |
|---|---|
| `Line.__post_init__` | 없는 선에 밴드를 채우면 **터진다**. 정의 밖 밴드·선 이름·confidence 범위도 |
| `_assert_no_conclusions` | 측정값에 `"이상주의적"` 같은 결론이 섞이면 **터진다** |
| `decide()` | 거절 사유와 **행동**을 함께 낸다 |
| `to_prompt_block()` | 거절된 값으로는 실행되지 않는다 |
| `verify_output()` | LLM 문장의 금칙어·근거 없는 언급을 잡는다 |

`_assert_no_conclusions` 가 이 파일의 핵심이다. 손금 문서의 L2 규칙 엔진은
`감정선 종료점이 검지 아래 → 이상주의적` 형태였다. **그건 매핑이지 측정이 아니다.**
`behavior_mapper.py` 의 "목이 많으면 성장형이다" 금지, `relation_engine.py` 의
태그 가드와 같은 원칙이고 같은 방식으로 막는다.

## band-flip 테스트가 왜 필요한가

결정론 시험("같은 손 → 같은 키")은 **아무것도 안 보고 항상 같은 답을 내도 통과한다.**
그래서 반대 방향을 함께 시험한다 — 밴드를 뒤집으면 키와 프롬프트가 **반드시** 바뀌어야 한다.

이게 이 도메인에서 유일하게 의미 있는 회귀 테스트다.
통과하지 못하면 CV 파이프라인 전체가 장식이 된다.

## 산출물 검증

`verify_output()` 이 LLM 문장을 되받아 검사한다.
Structured Output 은 **형태만** 보장한다. 내용은 여기서 본다.

- **금칙어**: 수명·사망·질병·진단·치료·결혼 시기·임신, 그리고 `반드시`·`확실히`·`100%`
- **근거 없음**: 관측되지 않은 선을 언급했는가

면책 문구는 검사하지 않는다. **앱이 locale 별 승인 문구로 마지막에 덮어쓴다** —
LLM 이 만든 면책 문구를 믿지 않는다.

## 저장하지 않는 것

원본 이미지, EXIF, 그리고 **개인을 식별할 수 있는 팜코드.**
"내 손 기억하기" 같은 매칭 기능을 붙이는 순간 생체인식 특징정보를 다루게 된다.
이 파일은 그런 값을 만들지도 반환하지도 않는다.
(일반 정보이며 법률 자문이 아니다. 출시 전 법률 검토가 필요하다.)

## 아직 없는 것 — CV 파이프라인

이 파일은 **계약과 판정**이다. 실제 측정은 아직 없다.

| 단계 | 상태 |
|---|---|
| MediaPipe 21 랜드마크 · `is_palm_side` 판정 | ⬜ |
| 정규 팜 좌표계 (손목0–중지MCP9 종축, 검지MCP5–새끼MCP17 횡축, 512×512 어파인) | ⬜ |
| 조명 나눗셈 + CLAHE · 채널 자동 선택(LAB-L vs 블루) | ⬜ |
| Frangi/Gabor 융합 → 세선화 → 폴리라인 추적 | ⬜ |
| 헝가리안 매칭 선 분류 | ⬜ |
| persistent feature (임계 ±10% 에서 살아남는 것만) | ⬜ |

**Hough/LSD 를 최종 표현에 쓰지 않는다.** 직선 검출기라 곡률이 파괴되는데,
감정선·두뇌선·생명선은 본질적으로 곡선이고 곡률이 해석의 핵심이다.
시드로만 쓴다. 이건 협상 대상이 아니다 (두 모델 공통 경고).

CV 계층은 이미지와 실제 장치가 있어야 만들 수 있다.
**그때까지 이 계약이 먼저 서 있는 것이 맞다** — 계약이 없으면
CV 가 무엇을 내놓아야 하는지 모른 채 만들게 된다.

검증: `python3 test_palm_features.py` — 28/28 통과해야 한다.

# 리포트 조립 (`report_composer.py`)

`weights` · `relation_engine` · `palm_features` 는 각자 조각을 내놓는다.
**이 파일이 그것을 하나의 프롬프트로 묶고, 돌아온 문장을 되받아 검사한다.**

## 이 앱의 존재 이유 — 바넘을 막는다

세상의 모든 운세 앱은 이런 문장을 쓴다.

> "겉으로는 강해 보이지만 속으로는 여린 면이 있습니다"
> "아직 발휘하지 못한 잠재력이 많습니다"
> "때로는 외향적이고, 때로는 신중합니다"

**전부 맞는다. 누구에게나 맞기 때문이다.** 이것이 바넘(포러) 효과다.
읽는 사람은 "어떻게 알았지?" 하고, 그 감탄은 며칠 안에 식는다.

우리는 그 문장을 **코드로 막는다.** 두 가지 방법으로.

### ① 문장 패턴 탐지 (`barnum_flags`)

| 패턴 | 예 |
|---|---|
| 양면 병치 | "겉으로는 ~지만 속으로는 ~" · "때로는 ~ 때로는 ~" |
| 보편 수식어 + 근거 없음 | "대체로 신중한 편입니다" |
| 보편 욕구 | "인정받고 싶은", "발휘하지 못한 잠재력" |

**완충어가 있어도 근거를 가리키면 통과시킨다.**
"때로는 감정선이 흐려 보일 수 있습니다" 는 바넘이 아니다 — 잰 것을 말하고 있다.

### ② 포러 겹침 측정 (`forer_overlap`) — 이게 본체다

**서로 다른 사람의 리포트 두 개에 같은 문장이 있으면 그건 개인화가 아니다.**

```
개인화된 두 사람 :  0%   기준 이내
바넘 두 사람     : 67%   > 기준 30% — 서로 다른 사람에게 같은 문장이 나갔다
```

①은 규칙이라 우회당할 수 있다. **②는 결과를 직접 잰다.**
"안 맞는 말을 안 한다"를 주장이 아니라 **숫자**로 만드는 지표다.

`MAX_FORER_OVERLAP = 0.30` — 이 게이트를 낮추지 않는다.

## 근거 비율

문장마다 근거를 요구하지는 않는다 — 연결 문장·전환 문장은 있어야 한다.
대신 **리포트 전체에서 재료를 가리킨 문장의 비율**을 본다.

```
MIN_GROUNDED_RATIO = 0.40
```

미만이면 `근거부족` 위반이다. 사업계획서의 "모든 문장은 E-번호를 단다" 와 같은 규율이고,
글의 성격이 달라 비율로 완화했을 뿐이다.

## 재료가 없으면 만들지 않는다

```python
RC.compose()   # 축이 하나도 없음
→ ValueError: 축이 하나도 없다. 이 상태로는 리포트를 만들지 않는다.
              재료 없이 쓴 글은 반드시 바넘이 된다.
```

그리고 **거절된 손금 측정값은 여기까지 오지 못한다** — `to_prompt_block()` 이 막는다.
문이 하나뿐이라 우회로가 없다.

## 빠진 축을 독자에게 밝힌다

```
이 해석에서 빠진 근거: 관계, 맥락 — 자료가 없어 반영하지 않았습니다.
```

`note_for_reader()` 가 만드는 이 문장을 리포트 근거란에 그대로 싣는다.
빠진 축을 조용히 재분배하면 **왜 그 해석이 나왔는지 나중에 설명할 수 없다.**

## 면책 문구는 LLM 이 쓰지 않는다

프롬프트에 `{{DISCLAIMER}}` 자리를 두고, LLM 에게 **쓰지 말라고 명시**한다.
앱이 locale 별 승인 문구로 마지막에 덮어쓴다.

그리고 LLM 이 그래도 썼는지 `verify_report()` 가 검사한다 (`면책침범`).
다국어 환경에서 면책이 누락되거나 뉘앙스가 새는 것을 막는다.
