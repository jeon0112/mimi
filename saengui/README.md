# 생의 무늬 — 가중치 모듈

엔진 본체는 VPS `/opt/data/saengui-munui/backend/` 에 있다.
여기에는 **가중치 표 하나만** 둔다. 그것이 가장 많이 바뀌고, 가장 조용히 틀어지는 값이기 때문이다.

```
saengui/
├── weights.py        ← VPS engines/weights.py 로 배치
├── test_weights.py   ← 배치 후 VPS에서 실행해 통과 확인
└── README.md
```

---

## 바뀐 것

**이전** — 한 표에 성격이 다른 것이 섞여 있었다.

```
행동 45% + 맥락 30% + MBTI 20% + 사주 5%
```

**이후** — 표를 둘로 나눴다.

### ① 증거 축 (합 100) — 무엇이 사실인가

| 축 | 비중 | 변화 |
|---|---:|---|
| 행동 — 실제로 한 것·기록한 것 | 40% | 45 → 40 |
| **관계 — 오행 교환(생·극·합·충)** | **25%** | **신설** |
| 맥락 — 지금의 상황·감정·관심 | 25% | 30 → 25 |
| 타고난 지표 — 사주 5 + 손금 5 | 10% | 5 → 10 |

### ② 형식 층 (가중치 없음) — 어떻게 말할 것인가

| 층 | 역할 |
|---|---|
| 주역 64괘 | 리포트의 서사 골격 |
| MBTI | 어휘와 톤 |
| 손금 오버레이 | 물증·개인화 지각(신뢰) |

**MBTI와 주역은 근거가 아니라 말하는 방식이다.** "무엇이 사실인가"에 기여하지 않는 것에
가중치를 주면 비중 싸움이 되고, "주역이 몇 퍼센트 맞았나"라는 답할 수 없는 질문이 생긴다.

형식 층으로 내려간다고 역할이 줄지 않는다. 오히려 커진다 —
주역은 모든 리포트의 뼈대가 되고, MBTI는 모든 문장의 톤이 된다.

## 코드가 스스로 지키는 것

숫자만 옮기면 몇 달 뒤 조용히 되돌아간다. 그래서 판단을 코드에 박았다.

| 장치 | 하는 일 |
|---|---|
| `_validate()` (import 시 실행) | 합이 100이 아니면 **앱이 안 뜬다** |
| `FORBIDDEN_IN_EVIDENCE` | `MBTI`·`주역`·`64괘` 를 증거 축에 넣으면 **터진다** |
| `resolve(available)` | 데이터 없는 축을 재정규화하되 **빠진 축을 함께 돌려준다** |
| `prompt_block()` | 프롬프트에 숫자를 손으로 적지 않게 한다 |
| `cache_key()` | 표를 고치면 캐시가 무효화된다 |

`resolve()`가 빠진 축을 돌려주는 이유: 관계 축은 신설이라 초기 사용자에게 데이터가 없다.
25%를 그냥 없애고 나머지를 늘리면 **왜 그 해석이 나왔는지 나중에 설명할 수 없다.**
빠진 것은 빠졌다고 리포트 근거란에 남긴다.

## VPS 이관 절차

```bash
# 1. 배치
#    저장소 saengui/weights.py → /opt/data/saengui-munui/backend/engines/weights.py

# 2. 검증 — 반드시 VPS에서 실행한다
cd /opt/data/saengui-munui/backend/engines
python3 test_weights.py        # 17/17 통과해야 한다. 하나라도 실패하면 멈춘다.

# 3. llm_writer.py 연결
#    기존에 하드코딩된 45/30/20/5 를 찾아 지우고 아래로 바꾼다
```

```python
from weights import prompt_block, cache_key

# 사용 가능한 축 이름을 넘긴다. 데이터가 없는 축은 넣지 않는다.
available = {"행동", "맥락", "타고난지표"}   # 관계 데이터가 생기면 "관계" 추가
block = prompt_block(available)             # 프롬프트에 이 문자열을 그대로 끼운다
```

### 주의

- **`llm_writer.py` 는 아직 확인하지 못했다.** 현재 어떤 형태로 가중치를 쓰는지 모른다.
  파일을 열어 실제 코드를 보고 연결하되, **숫자를 두 곳에 적지 마라.**
  두 곳에 적힌 숫자는 반드시 갈라진다.
- 하드코딩된 값을 지웠는지 확인한다: `grep -n "45\|20\|MBTI" llm_writer.py`
- `quality_gate.py` Q09(자기선택 MBTI 구분)는 그대로 둔다. 이 변경과 충돌하지 않는다.
- 캐시를 쓰고 있다면 `cache_key()` 를 키에 포함시킨다.
  표를 고쳐놓고 옛 리포트가 계속 나오는 것이 가장 찾기 어려운 실패다.

## 아직 없는 것

`관계` 축은 가중치 25%를 배정받았지만 **이를 채울 엔진이 없다.**
`relation_engine.py` 는 설계 문서에만 있고 코드가 없다.

그때까지 `resolve()` 가 관계 축을 빼고 재정규화하며, 빠졌다는 사실을 함께 돌려준다.
**그 상태로 동작하는 것이 맞다.** 없는 축을 있는 척 채우지 않는다.
