## 2. 🔴 그런데 한 가지를 먼저 경고한다

> **「한눈에」에 값을 나열하는 것과, 본문 문장이 그 값을 쓰는 것은 다르다.**

```
한눈에:  일간 기(신약) · 편관·칠살(3개) · 대운 역행 · 진위뢰   ← 값이 있다
본문:    "무엇이든 심으면 기른다. 자기 자신은 드러나지 않는다"   ← 이 문장이
                                                              저 값을 쓰는가?
```

★★★★★ **값을 머리에 얹어 놓고 본문이 그대로면, 인용률 측정기는 통과하고 글은 안 변한다.**
**E-707 「실린 척한다」가 정확히 이 모양이다.**

**재는 법은 하나뿐이다 — 바꿔치기.**
다른 사람의 「한눈에」를 이 본문 위에 얹어도 말이 되면, 본문은 재료를 안 쓴 것이다.

**그러므로 화면을 고치기 전에 `material_citation()` 을 본문에만 돌려 본다.**
`report_composer.py` 에 이미 있다.

## 3. 화면에서 고칠 것 — 값으로

### ① 버그 — 「대운」이 두 번 나온다

```
✗  대운: 대운 방향: 역행
✓  대운  역행
```

라벨과 값이 겹쳤다. **한 줄이면 고친다.**

### ② 「한눈에」가 가운뎃점으로 한 줄에 뭉쳐 있다

```
✗  일간 기 (신약) · 주요 십성: 편관·칠살(3개) — 추진력, 모험, 권력,
   압박 속 성장 · 대운: 대운 방향: 역행 · 주역: 진 — 진위뢰
```

**네 가지가 한 문장처럼 이어져 어디서 끊기는지 안 보인다.**
★ **넷은 종류가 다르다 — 표나 칸으로 갈라야 읽힌다.**

### ③ 명식이 붙어 있다

```
✗  계묘을묘기묘임진
✓  년 계묘 · 월 을묘 · 일 기묘 · 시 임진
```

**네 기둥은 사주의 뼈대인데 지금은 여덟 글자 덩어리다.**

### ④ 카드가 세로로만 쌓인다

한눈에 → 일간 → … 로 계속 내려간다. **스크롤이 길다.**
★ **탭이나 접기**로 갈라야 한다 — 특히 **렌즈가 넷으로 늘면**(문서 30) 지금 구조로는 못 담는다.

### ⑤ 기록번호가 있는데 쓸 곳이 없다

★★★★★ **이것이 다음 절의 열쇠다.**

## 4. ★★★★★ 궁합 자리 — 기록번호가 열쇠다

**새 기재를 만들 필요가 없다.** 화면에 이미 `96d182b5c5cc` 가 있다.

```
내 기록번호  96d182b5c5cc
상대 번호    [            ]  →  [관계 보기]
```

★ **왜 이것이 좋은가**

| | |
|---|---|
| 개인정보를 **다시 안 받는다** | 생년월일시를 두 번 입력받지 않는다 |
| **번호만 교환한다** | 카톡으로 번호 한 줄 보내면 끝 |
| **초대가 저절로 된다** | 상대가 번호가 없으면 만들러 온다 — **사용자가 사용자를 데려온다** |
| 재료가 이미 저장돼 있다 | 번호로 명식을 꺼내면 된다 |

★★★ **그리고 이것이 어제 시저님이 말씀하신 「계속 돈을 지불하고 볼 만한 것」의 답이다.**
혼자 보는 해석은 한 번 보면 끝난다. **관계는 사람 수만큼 늘어난다.**

### 관계 화면에 무엇이 들어가나 — 엔진이 이미 정해 놨다

`relation_engine.analyze(a, b)` 가 내는 것 그대로 칸을 만든다.

| 칸 | 엔진이 주는 것 |
|---|---|
| ① 일간 음양 | **보완적** / **경쟁적** — *「양(기) × 음(을) — 다름」* |
| ② 천간 5합 | **천간합** · **극중생합** — *「극이 합으로 전환」* |
| ③ 오행 생극 | **상생** / **상극** / **동기** |
| ④ 비대칭 | `asymmetry` — ★ **누가 누구에게 더 기우나** |
| ⑤ 결실기 | `timing` 연도들. **모르면 「결실기미상」** — 비운 채로 |
| ⚠ 못 잰 단계 | `missing` — **화면에 그대로 보여준다.** 숨기지 않는다 |

★★★★★ **④ 비대칭이 제일 흥미롭고 아무도 안 한다**(문서 29 §2).
*「나는 이 사람에게 기대는데, 이 사람은 나에게 안 기댄다」* — **점수 하나로는 절대 안 나오는 말이다.**

### 🔴 점수 하나는 죽은 설계다

```
✗  "궁합 78점"        ← 무슨 뜻인지 아무도 모른다. 그리고 다시 볼 이유가 없다
✓  축마다 다른 답      ← 일은 보완적인데 감정은 경쟁적이다 — 이게 이야기다
```

**문서 29 §3 에 이미 적혀 있다. 그대로 간다.**

## 5. 주변 사람으로 넓히는 기재

시저님이 *「궁합과 주변 사람으로 확장하는 기재」* 라고 하셨다.

```
내 사람들
 ├ 이름표만 붙인다 (번호 + 내가 부르는 이름)
 ├ 관계 종류를 고른다: 배우자 · 동업 · 상사 · 부모 · 친구
 └ 한눈에 보는 판 — 누가 나를 생(生)하고 누가 극(剋)하나
```

★ **같은 엔진이 그대로 돈다.** 사람이 한 명이든 열 명이든 `analyze(나, 상대)` 를 반복할 뿐이다.
**렌즈 구조**(문서 30)가 여기서 값을 낸다 — **재료는 하나, 보는 각도만 늘어난다.**

🔴 **다만 개인정보 규율을 지킨다.**
- **상대의 생년월일시를 우리가 받지 않는다.** 번호로만 본다
- 상대가 자기 기록을 안 만들었으면 **관계를 못 본다.** 추측해서 만들지 않는다
- 「내 사람들」 목록은 **내 브라우저에만** 둘지, 서버에 둘지 **따로 정한다** — 서버에 두면 관계망이 쌓인다
