# 그래프에 무엇을 담을 것인가

> 2026-09-08 · Neo4j(`mungkle-neo4j`) 현재 노드 6개 — 사실상 빈 그래프.
> **먼저 기준을 세운다.** "다 넣자"로 시작한 그래프는 못 쓴다.

---

## 1. 기준 — 연결이 곧 답인 것만 담는다

| | 잘하는 것 | 못하는 것 |
|---|---|---|
| **벡터 검색 (RAG)** | **비슷한 것**을 찾는다 | 연결을 따라가지 못한다 |
| **그래프** | **연결된 것**을 따라간다 | 비슷함을 모른다 |

> ### 담을지 말지는 한 가지로 정한다.
> **"이것이 저것과 연결되어 있어서 생기는 질문"이 있는가?**

「비슷한 문서를 찾아줘」로 풀리면 → **벡터에 둔다.**
「이게 무너지면 뭐가 같이 무너지나」로 물어야 하면 → **그래프에 담는다.**

그래프는 저장소가 아니라 **질문 도구**다. 물을 질문이 없는 것은 넣지 않는다.

---

## 2. 담을 것 — 다섯 갈래, 순서대로

### ① 관계 — 사람 · 법인 · 프로젝트

뭉클이 기억의 **뼈대**다. 대화 내용은 벡터로도 찾지만, **누가 무엇의 무엇인가**는 못 찾는다.

```
(자광 전) -[돕는다]->  (주식회사 블루바이오)
(노대표)  -[사내이사]-> (주식회사 블루바이오)
(협회)    -[별개 법인]-> (주식회사 블루바이오)
(협회)    -[형태]->     (사단법인 · 비영리)
```

**실제로 필요했던 질문** (2026-09-07 광주TP)
> "이 공고에 협회 이름으로 신청할 수 있는가?"

법인 형태 · 소재지 · 설립일 · 관계 — 이걸 매번 시저님께 여쭸다.
그래프에 있으면 한 번 물어보고 끝난다.

### ② 근거 원장 — 주장 ↔ 근거 ↔ 출처

`proposals/LEDGER.md` 의 그래프판.

```
(주장) -[근거로 한다]-> (근거 E-번호) -[출처]-> (커밋 · 실측 · 문서)
```

**실제로 겪은 일** (2026-09-06 온디바이스AI)
> *"청소 현장 데이터는 우리 것이다"* 한 문장이 무너지자
> 독창성 15 + 기술경쟁력 15 + 적용계획 20 + 가산 3 이 **동시에** 빠졌다.

**그걸 안토니우스가 손으로 셌다.** 그래프면 한 번 물으면 나온다.

> "E-03 이 거짓으로 밝혀지면 어떤 주장들이 같이 무너지는가?"

계획서가 한 개일 땐 손으로 센다. **여러 개가 같은 근거를 가리키면 못 센다.**

### ③ 공고 · 기관 지식 — 공고가 끝나도 안 죽는 것

공고는 마감되면 죽지만, **기관에 붙은 사실은 산다.**

```
(광주테크노파크) -[받지 않는다]-> (비영리법인)
(광주테크노파크) -[판정 기준]->   (사업 내용)      ※ 업종코드 아님
(광주테크노파크) -[요구]->        (비교견적 3장)
(KETI)          -[허용]->        (기획 단계 신청)
(KETI)          -[허용]->        (NPU 미정 기재)
```

**사흘간 공고 두 개를 해부하며 알아낸 것들이다.** 지금은 각 폴더 안에 흩어져 있다.
다음에 같은 기관 공고가 오면 **처음부터 다시 전화해야 한다.**

물을 질문
> "우리 자격으로 신청 가능한 공고 유형은?"
> "이 서류를 요구하는 기관이 또 어디인가?"

### ④ 코드 · 인프라 지도 — **부재가 눈에 보인다**

```
(money_engine_data_collector.py) -[읽는다]-> (주가 CSV)
(data_fetcher.py)                -[쓴다]->   (주가 CSV)
(크론 3cabeaac)                  -[부른다]-> (money_engine_data_collector.py)
   ???                           -[부른다]-> (data_fetcher.py)     ← 아무도 없다
```

**오늘·어제 세 번 겪은 문제가 이것 하나로 드러난다.**

| | 물었던 것 | 답 |
|---|---|---|
| E-25 | "펀딩비 수집이 왜 실패하나" | 호출한 적이 없다 |
| E-26 | "CSV 갱신이 왜 멈췄나" | 돌린 적이 없다 |
| E-27 | "Neo4j 접속이 왜 안 되나" | 붙은 적이 없다 |

셋 다 **"소비자는 있는데 생산자가 없다"** 였다.
그래프에서는 **들어오는 화살표가 없는 노드**로 한눈에 보인다.

> "이 데이터를 만드는 것이 누구인가?" — 답이 비면 그게 답이다.

### ⑤ 실패 계보 — 같은 형태를 두 번째에 알아챈다

```
(E-25) -[같은 형태]-> (부재를 고장으로 착각)
(E-26) -[같은 형태]-> (부재를 고장으로 착각)
(E-27) -[같은 형태]-> (부재를 고장으로 착각)
```

**안토니우스는 세 번째에야 알아챘다.** 그래프였으면 두 번째에 알았다.
그리고 이건 **뭉클이가 스스로 배우는 구조**가 된다 — 새 증상이 오면
"전에 이 형태를 본 적이 있는가"를 물을 수 있다.

---

## 3. 담지 않을 것

| 넣지 않는다 | 이유 |
|---|---|
| 대화 원문 | 벡터가 잘한다. 그래프는 무거워지기만 한다 |
| 문서 본문 | 〃 |
| 시세·로그 같은 시계열 | 그래프의 일이 아니다 |
| "언젠가 쓸 것 같은 것" | **이 한 줄이 그래프를 죽인다** |

---

## 4. 넣는 문을 하나로 만든다 — 이게 제일 중요하다

그래프가 망하는 방식은 **못 써서**가 아니라 **쓰레기가 쌓여서**다.
뭉클이가 자유롭게 넣게 두면 반년 뒤 아무도 못 믿는 그래프가 된다.

`saengui/palm_features.py` 에서 쓴 방식을 그대로 가져온다 —
**품질 미달 측정값은 `to_prompt_block()` 이 막는다. 문이 하나뿐이라 우회할 수 없다.**

### 모든 노드가 반드시 갖는 것

| 속성 | 뜻 |
|---|---|
| `source` | 어디서 왔나 (커밋 해시 · 파일 경로 · 통화 기록 · 실측) |
| `asserted_by` | 누가 넣었나 (시저님 · 안토니우스 · 뭉클이) |
| `asserted_at` | 언제 |
| `confidence` | `확인` / `기록` / `추정` — **원장의 근거유형과 같은 말** |

**`source` 가 없으면 들어가지 못한다.** 원장 규칙 그대로다 —
*가리킬 행이 없으면 그 문장은 쓰지 않는다.*

### 뭉클이의 쓰기 — 허용한다 (시저님 결정 2026-09-08). 다만 문을 통과해서만

**뭉클이는 Cypher 를 직접 쓰지 않는다.** 함수 두 개로만 쓴다.

```
assert_node(label, key, props, *, source, asserted_by, confidence)
assert_edge(from_key, rel, to_key,  *, source, asserted_by, confidence)
```

이 함수가 **넣기 전에 막는다.**

| 막는 것 | 왜 |
|---|---|
| `source` 가 비었거나 "내부 자료" 류 | 다시 찾아갈 수 없는 출처는 출처가 아니다 |
| `confidence` 가 `확인`/`기록`/`추정` 밖의 값 | 원장 근거유형과 어긋나면 둘이 갈라진다 |
| 정의되지 않은 라벨·관계 이름 | 스키마가 조용히 번지는 것을 막는다 |
| 같은 사실을 다른 `confidence` 로 덮어쓰기 | **추정이 확인을 덮는 것을 막는다** |

`saengui/palm_features.py` 와 같은 방식이다 —
품질 미달 값은 `to_prompt_block()` 이 `PalmContractError` 로 막는다.
**문이 하나뿐이라 우회할 수 없다.**

> **쓰기를 허용한다 = 이 함수를 쓸 수 있다.**
> Cypher 직접 실행 권한을 준다는 뜻이 아니다.

그리고 **함수가 서기 전에는 쓰기가 열리지 않는다.** 순서가 반대면
첫 달에 쌓인 것을 나중에 걸러내야 하고, 그게 훨씬 비싸다.

### 지우지 않는다

틀린 것으로 밝혀져도 노드를 삭제하지 않는다.
`상태: 폐기` + 사유를 붙인다. **무엇이 왜 틀렸는지가 다음 판단의 재료다.**
(원장 「행 추가 규칙」 1번과 같다)

## 5. 무엇부터 넣을까 — **② 근거 원장**

다섯 중 ②로 시작한다. 이유는 셋이다.

**하나. 이미 구조화되어 있다.**
`LEDGER.md` 는 이미 표다. E-01~E-27, 각 행에 근거유형·출처·측정시점이 있다.
**새로 지어낼 것이 없다.** ①(관계)로 시작하면 "기억이란 무엇인가"부터 정해야 한다.

**둘. 물을 질문이 이미 있다.**
"이 근거가 무너지면 무엇이 같이 무너지나" — 실제로 물었고, 손으로 셌다.

**셋. 규율이 같이 들어온다.**
원장은 이미 「출처 없으면 안 쓴다」로 만들어진 것이다.
그걸 그대로 옮기면 **§4의 문이 저절로 지켜진다.** 첫 데이터가 규율을 가르친다.

### 그다음 순서

```
② 근거 원장   ← 첫 번째. 이미 표다
④ 코드 지도   ← 두 번째. 부재를 드러낸다. 기계로 뽑을 수 있다
③ 공고·기관   ← 세 번째. 공고가 쌓이면 값어치가 커진다
① 관계        ← 네 번째. 범위를 정하기 어렵다. 뒤로 미룬다
⑤ 실패 계보   ← ②가 들어가면 거의 따라온다
```

**한 번에 하나씩.** 두 갈래를 동시에 넣으면 스키마가 엉키고, 엉킨 스키마는 다시 뜯어야 한다.

## 6. 아직 정하지 않은 것

| 항목 | 상태 |
|---|---|
| 노드 라벨·관계 이름 확정 | 미정 — ② 넣을 때 정한다 |
| 원장 → 그래프 적재 방법 (수동/스크립트) | 미정 |
| ~~뭉클이가 쓰기도 할 것인가~~ | **허용 (2026-09-08 시저님 결정)** — 단 `assert_*` 함수 경유 |
| `assert_node` / `assert_edge` 구현 | **미착수 — 쓰기의 전제조건** |
| 기존 노드 6개의 정체 | 미확인 |

**뭉클이의 쓰기 권한이 제일 중요한 결정이다.**
읽기만 하면 그래프는 깨끗하지만 자라지 않는다.
쓰게 하면 자라지만 §4 의 문이 코드로 막혀 있어야 한다. 말로는 안 된다.
