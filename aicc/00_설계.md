# AICC — 설계

> 2026-09-06 착수 · 인바운드 1차 상담·안내 / 웹 음성 위젯
> **이 문서는 엔지니어링 설계다.** 사업·영업 내용은 여기 쓰지 않는다 (저장소가 Public).

---

## 0. 이 프로젝트가 지난번과 다른 점

한 번 만들어서 배포까지 했고, **품질·자연스러움·속도**에서 멈췄다.
같은 자리에서 다시 멈추지 않기 위해 규칙 하나를 먼저 세운다.

> ### 느리다고 말하지 않는다. 어디가 몇 ms 인지 말한다.

"느리다"는 진단이 아니다. 음성 대화의 지연은 다섯 구간이고,
구간을 안 쪼개면 **엉뚱한 데를 고친다.** 모델을 아무리 빠른 것으로 바꿔도
말끝 판단에 800ms를 쓰고 있으면 800ms 다.

---

## 1. 지연 구조 — 무엇을 재는가

사람이 "끊겼나?" 하고 느끼는 것은 **응답 완성 시간이 아니라 첫 소리까지의 시간**이다.

```
사용자 말 끝
  │
  ├─ ① 말끝 판단 (endpointing)      ← 가장 자주 범인. 모델과 무관하다
  ├─ ② STT 확정
  ├─ ③ LLM 첫 토큰 (TTFT)           ← Flash 가 고치는 유일한 구간
  ├─ ④ TTS 첫 오디오 바이트
  └─ ⑤ 네트워크·버퍼
  ▼
첫 소리
```

### 목표 예산 — **목표치다. 실측이 아니다.**

| 구간 | 목표 |
|---|---:|
| ① 말끝 판단 | 250 ~ 400 ms |
| ② STT 확정 (부분결과 선행 처리 시) | ~ 50 ms |
| ③ LLM 첫 토큰 | 150 ~ 350 ms |
| ④ TTS 첫 바이트 | 100 ~ 250 ms |
| ⑤ 네트워크·버퍼 | 50 ~ 150 ms |
| **합계 (첫 소리까지)** | **≤ 800 ms** |

**선발화(§3)를 쓰면 체감 지연은 ①+⑤ 수준으로 떨어진다.** 300~500ms 대다.

이 표의 숫자는 전부 **가설이다.** 실측이 나오면 이 표를 실측으로 덮어쓴다.
안 맞으면 안 맞는 대로 적는다.

## 2. 파이프라인

```
브라우저 마이크
   │ (WebSocket 단일 연결 — HTTP 왕복 금지)
   ▼
 VAD ── 1차: 브라우저(에너지)  2차: 서버
   ▼
 STT (스트리밍, 부분결과 사용)
   ▼
 대화 관리 ──────► 지식베이스
   ▼
 LLM (토큰 스트림)
   ▼
 문장 분할 ──► TTS (문장 단위 스트리밍)
   ▼
브라우저 스피커
```

**전송은 WebSocket 하나로 묶는다.** 오디오 프레임이 올라가고 오디오 청크가 내려온다.
요청/응답 왕복을 쓰면 ⑤가 구간마다 반복된다.

## 3. 자연스러움을 만드는 세 장치 — 구조가 8할, 모델이 2할

지난번을 무너뜨린 것은 대부분 모델이 아니라 이 세 개의 부재다.

### ⓐ 선발화 (filler)

의도 분류가 끝나기 전에 **"네, 확인해 볼게요"** 같은 짧은 고정 음성을 즉시 재생한다.
사람도 그렇게 한다. 뒤에서 실제 처리가 돌아간다.

- 클립은 **미리 생성해 캐시**한다. 이 소리를 만드느라 지연이 생기면 본말전도다.
- 종류를 여러 개 두고 돌린다. 같은 소리가 반복되면 기계임이 드러난다.

### ⓑ 끼어들기 (barge-in)

사용자가 말을 시작하면 **TTS 즉시 중단 · 재생 큐 비우기 · LLM 요청 취소.**
이것이 없으면 어떤 튜닝으로도 자연스러워지지 않는다. 사람은 남의 말을 자른다.

### ⓒ 문장 단위 스트리밍

LLM 토큰이 나오는 대로 문장 경계를 찾아 **즉시 TTS 큐에 넣는다.**
응답이 끝나기를 기다리지 않는다.

- 한국어 문장 경계는 `.?!` 만으로 부족하다. 종결어미(`~요`, `~다`, `~까`)를 함께 본다.
- **첫 문장을 짧게 뽑도록 프롬프트로 유도한다.** 첫 문장 길이가 곧 ④의 크기다.

## 4. 모델 배치

| 일 | 모델 | 근거 |
|---|---|---|
| 의도 분류 · 슬롯 추출 · 짧은 되묻기 | **GLM-5.3-Flash** | 짧고 잦다. 지연이 전부이고 판단이 얕다 |
| 지식 기반 답변 | GLM-5.3 | 정확도가 필요한 턴 |
| 판정 어려운 턴 | 상위 모델로 승격 | **나중.** 지금 넣으면 지연 예산을 못 맞춘다 |

**처음에는 Flash 단일로 시작한다.** 계층화는 예산을 맞춘 뒤의 최적화다.
지연도 못 맞춘 상태에서 라우팅을 넣으면 무엇이 원인인지 다시 알 수 없게 된다.
(오늘 아침 교훈 — 하루에 두 가지를 바꾸면 어느 쪽이 범인인지 못 가린다.)

## 5. 품질 — AICC 가 망하는 진짜 이유

느려서 망하지 않는다. **모르는 것을 아는 척해서** 망한다.
한 번 틀린 답을 자신 있게 말하면 그 뒤의 모든 답을 못 믿게 된다.

그래서 `saengui/report_composer.py` 의 규율을 그대로 가져온다.

| 손금 앱 | AICC |
|---|---|
| `is_grounded()` — 문장이 측정값을 가리키는가 | 답변이 지식베이스 항목을 가리키는가 |
| `barnum_flags()` — 누구에게나 맞는 말 차단 | 아무 질문에나 맞는 말 차단 |
| `verify_report()` — 내보내기 전 검사 | **말하기 전** 검사 |

**규칙**

1. 지식베이스에 없으면 **지어내지 않는다.** → "그건 담당자가 확인해서 연락드리겠습니다"
2. 넘기는 것은 실패가 아니라 **설계된 동작**이다. 넘긴 비율을 지표로 잰다.
3. 숫자·날짜·가격은 **원문 그대로**만 말한다. 계산해서 말하지 않는다.

> 없는 값은 지어내지 않는다. 비면 비운 채로 둔다.
> 이 프로젝트에서는 **"모르겠습니다"가 정답인 경우가 있다.**

## 6. 지식베이스 — 조기 최적화 금지

1차 상담이면 본체는 FAQ 다.

- **작을 때는 프롬프트에 통째로 넣는다.** 검색을 붙이지 않는다.
  검색은 지연(②~③ 사이)을 만들고, 틀린 문서를 물어오면 §5가 무너진다.
- 넣기 어려울 만큼 커지면 그때 검색을 붙인다. **그때**다.

---

## 7. 계측 — 만들기 전에 재는 틀부터

모든 턴에 구간별 타임스탬프를 남긴다. 로그가 아니라 **구조화된 기록**이다.

```
turn_id, t_speech_end, t_endpoint, t_stt_final,
t_llm_first_token, t_tts_first_byte, t_audio_out,
barge_in(bool), filler_used(bool), escalated(bool), model
```

**"안 일어난 일은 로그에 안 남는다"** 를 여기서 미리 막는다 (오늘 여섯 번째 사례).
선발화가 안 나갔으면 `filler_used=false` 가 남아야 한다. 라인이 없는 것으로
없었음을 표현하지 않는다.

## 8. 단계

| 단계 | 내용 | 끝났다는 기준 |
|---|---|---|
| **0** | 지난 시범의 흔적 조사 | 무엇을 썼는지 목록이 나온다 |
| **1** | 계측 틀 + 최소 왕복 루프 | §7 필드가 실제로 찍힌다 |
| **2** | 구간별 실측 → §1 표를 실측으로 교체 | 어디가 범인인지 숫자로 말할 수 있다 |
| **3** | 선발화 · 끼어들기 · 문장 스트리밍 | 첫 소리 ≤ 800ms |
| **4** | 지식베이스 + §5 검증 | 모르는 질문에 지어내지 않는다 |
| **5** | 웹 위젯 마감 | 남에게 보여줄 수 있다 |

**2단계를 건너뛰지 않는다.** 건너뛰면 지난번과 같은 자리에서 멈춘다.
