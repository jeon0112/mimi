# n8n 전략 자문 위원회 (사회자 선택 소집형)

`strategy_council.json` — 텔레그램 또는 웹 채팅으로 수시로 대화하는 **실시간 전략 상담 파트너**.
나라장터 입찰 워크플로우와는 별개. 모든 답변은 구글 드라이브에 자동 기록되어 **전략 아카이브**가 쌓인다.

## 핵심 구조 — 사회자가 관련 위원만 소집

```
텔레그램 입력 ┐
웹 채팅 입력 ┘→ 입력 정규화(채널·메시지·세션 통일)
  → 사회자(Sonnet, 구조화 출력) : 질문 보고 관련 위원 2~4명 key 선택
  → 명단 구성(Code) : roster에서 선택된 위원의 페르소나 꺼냄 (위원 수만큼 item 생성)
  → 위원 에이전트(Sonnet) : item마다 1회씩 반복 실행 (페르소나를 매번 교체)
       └ 도구: 네이버 뉴스/블로그/쇼핑/웹문서 검색 + 계산기
  → 의견 라벨 → 한 건으로 모으기(Aggregate)
  → 총괄 시너지 에이전트(Opus + 대화 기억) : 소집된 의견 종합
       ├→ 시트 누적 기록(구글 시트 append, 매 상담 1행)  (양 채널 공통)
       └→ 채널 분기 ─ telegram → 텔레그램 응답
                    └ web      → 웹 채팅으로 반환
```

## 위원 리서치 도구 (네이버 검색)

`위원` 에이전트에 검색/리서치 도구 6종 + 계산기를 붙였다.
마케팅·재무 위원이 소집되면 추측 대신 **실제 시장·경쟁사·가격·트렌드 데이터를 직접 조사**한다.

| 도구 | 종류 | 용도 |
|------|------|------|
| 네이버 뉴스/블로그/쇼핑/웹문서 검색 | 네이버 Open API (GET) | 동향·후기·가격대·자료 |
| 네이버 데이터랩 트렌드 | 네이버 Open API (POST) | 검색어 관심도(수요·계절성) 12개월 추이 |
| 웹검색 (SerpAPI) | SerpAPI 빌트인 노드 | 광범위·해외 정보 (구글 검색) |
| 계산기 | 빌트인 | CAC·LTV 등 수치 계산 |

- **네이버 인증**: 검색/데이터랩 노드 헤더의 `X-Naver-Client-Id / X-Naver-Client-Secret`을
  `={{ $env.NAVER_CLIENT_ID }}` / `={{ $env.NAVER_CLIENT_SECRET }}`로 읽음.
  - 환경변수 접근이 막혀 있으면(`N8N_BLOCK_ENV_ACCESS_IN_NODE=true`) 값을 직접 입력하거나
    **HTTP Custom Auth 자격증명**으로 두 헤더를 넣어라.
  - 키 발급: 네이버 개발자센터에서 애플리케이션 등록 → 검색 API + 데이터랩 사용 설정.
- **SerpAPI**: serpapi.com에서 API 키 발급 → n8n `SerpApi` 자격증명 생성 →
  `웹검색 (SerpAPI)` 노드에 선택 (`REPLACE_SERPAPI_CRED_ID`).
  - Tavily를 쓰려면 이 노드를 `toolHttpRequest`(POST `https://api.tavily.com/search`,
    헤더 `Authorization: Bearer <키>`, 본문 `{"query":"{query}","max_results":5}`)로 교체.
- 데이터랩 트렌드 노드는 POST 본문에 n8n 표현식(날짜)과 `{keyword}` 플레이스홀더가
  함께 들어가므로, import 후 한 번 실행해 응답이 정상인지 확인 권장.

### 왜 이 구조인가 (노드 안 꼬임)
- 위원마다 노드를 만들지 않는다. **위원 에이전트는 단 1개**, 소집된 위원 수만큼 자동 반복.
- 위원이 7명이든 20명이든 캔버스/노드 수는 **그대로**.
- 사회자가 질문당 2~4명만 부르므로 매 질문 호출 수가 적다 → **빠르고 저렴**.

## 위원 명단 (roster) — `명단 구성` Code 노드 안에 정의

| key | 위원 | 담당 |
|-----|------|------|
| planning | 기획·구조화 위원 | 목표·단계·KPI |
| critic | 현실성 검수 위원 | 리스크·실현가능성 (악마의 변호인) |
| legal | 법률·규제 위원 | 계약·지재권·개인정보·공공조달 |
| scale | 확장·디자인 위원 | 시스템 구조·UX·로드맵 |
| finance | 재무·투자 분석 위원 | 수익모델·밸류에이션·주식/시장 리서치 |
| marketing | 마케팅 위원 | 타깃·포지셔닝·채널·브랜딩 |
| admin | 조례·행정 고문 | 지방 조례 제정·행정절차·자치분권 (행정 전반 고문) |

### 위원 추가/수정 = Code 노드만 손대면 끝
1. `명단 구성` 노드 열기 → `ROSTER` 객체에 `key: { role, systemPrompt }` 한 줄 추가
2. `사회자` 노드 systemMessage의 위원 목록에 같은 key 한 줄 추가
3. `소집 명단 파서`의 `enum` 배열에 key 추가
→ **새 노드 0개.** 연결도 안 건드림.

## Import 후 세팅

1. **텔레그램 봇**: @BotFather로 토큰 → n8n Telegram API 자격증명 → `텔레그램 입력`/`텔레그램 응답`에 선택
2. **웹 채팅**: `웹 채팅 입력`(Chat Trigger)의 Chat URL 열면 바로 사용 (자격증명 불필요, 워크플로우 Active 필요)
3. **Anthropic**: 3개 모델 노드(사회자·위원·총괄)에서 자격증명 선택
4. **구글 시트 아카이브**: Google Sheets OAuth2 연결 → `시트 누적 기록` 노드에 선택 →
   `documentId`의 `REPLACE_SHEET_ID`를 스프레드시트 ID로 교체 (시트 URL `.../d/<이 부분>/edit`)
   - 첫 행(헤더)에 다음 6개 열을 만들어 두면 매 상담마다 1행씩 누적된다:
     `일시 | 채널 | 소집위원 | 질문 | 종합결론 | 위원의견`
   - sheetName(기본 `시트1`)이 실제 탭 이름과 같은지 확인.
   - 표 대신 문서 누적을 원하면 이 노드를 Google Docs(append) 노드로 교체 가능.
5. **네이버 검색**: 환경변수 `NAVER_CLIENT_ID` / `NAVER_CLIENT_SECRET` 설정(위 "리서치 도구" 참고)
6. 워크플로우 **Active** 토글

## 커스터마이즈 포인트

| 바꿀 것 | 위치 |
|---------|------|
| 위원 추가/페르소나 | `명단 구성` Code 노드 `ROSTER` + 사회자 목록 + 파서 enum |
| 소집 인원/기준 | `사회자` systemMessage (기본 2~4명) |
| 종합 답변 형식 | `총괄 시너지 에이전트` systemMessage |
| 기억 길이 | `대화 기억` `contextWindowLength` (기본 20턴) |
| 답변 품질 ↑ | `위원 모델`을 `claude-opus-4-8`로 상향 (비용·속도 trade-off) |
| 리서치 도구 추가/변경 | `위원` 에이전트에 toolHttpRequest 노드 추가 후 `ai_tool`로 연결 (예: 네이버 데이터랩 트렌드, SerpAPI 웹검색) |
| 아카이브 형식 | `시트 누적 기록`(구글 시트 append) → Google Docs append로 교체 가능 |

## 채널 메모
- **텔레그램 / 웹 채팅**: 둘 다 양방향 실시간.
- **카카오톡**: 개인 양방향 자동화는 공식 미지원. 단방향 알림톡은 비즈니스 채널 세팅 시 추가 가능.
