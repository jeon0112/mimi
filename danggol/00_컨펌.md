# 당골 컨펌 — 조건부 통과

> 2026-09-10 · 안토니우스 검수 · 뭉클이 구현 · 시저님 작명

---

## 판정

**조건부 통과.** 뼈대는 옳다. **기동 전에 셋을 채운다.**

---

## 먼저 — 잘한 것

| | |
|---|---|
| **N1~N8 거부 시험을 스스로 만들었다** | 시키지 않았는데 「안 되는 것」을 8건 시험했다. **오늘 가장 좋은 것** |
| 격리해서 돌렸다 | 실제 `stores/` 를 오염시키지 않았다 |
| 남는 문제 둘을 스스로 밝혔다 | N1 문구 · `chats.jsonl` 평문 |
| 규칙 기반이라 프롬프트 주입이 안 통한다 (N7) | ★ 이건 **한계가 아니라 자산**이다 (아래 §5) |
| 봇을 기동하지 않았다 | 토큰이 와도 Go 를 먼저 받겠다고 했다 |

---

## ★ 이 물건은 종류가 다르다

```
퀀트 · 그래프 · 사주   우리가 틀리면  →  우리가 손해
당골                   봇이 틀리면    →  남의 장사에 손해
```

**손님도 사장님도 우리가 모르는 사람이다.**
그래서 지금까지 쓰던 위험 목록으로는 부족하다.

---

## 기동 전 필수 — 셋

### ① 가게 지식이 낡으면 봇이 자신 있게 틀린다 ★

지금 구조는 옳다 — `stores/*.json` 에서 읽으니 **지어내지 않는다.**
**그런데 가격이 바뀌었는데 JSON 을 안 고치면?**

> **봇은 옛 가격을 자신 있게 말한다.**
> 지어낸 것이 아니라서 어떤 검사에도 안 걸린다.

**E-31 그대로다** — 낡은 값이 정상처럼 보인다.
그리고 이번엔 **손님이 그 값을 믿고 가게에 온다.**

**넣을 것**

| | |
|---|---|
| `stores/*.json` 에 `updated_at` | 언제 적은 정보인지 |
| 오래되면 사장님께 알림 | 예: 30일 넘으면 *"가격·영업시간이 그대로인가요?"* |
| 가격을 답할 때 기준일을 함께 | *"현재 안내드리는 가격은 O월 O일 기준입니다"* |

★ 마지막 것이 특히 싸고 강하다. **한 줄로 책임이 갈린다.**

### ② 「접수됐습니다」라 해놓고 사장님이 못 받으면 ★★

예약은 `reservations.jsonl` 에 쌓이고 텔레그램으로 전달된다.
**전달이 실패하면?**

> **손님은 「접수됐다」고 듣고, 사장님은 모른다. → 손님이 헛걸음한다.**

**E-40 그대로다** — 「했다」와 「닿았다」는 다르다.
어제 우리가 잡은 그 병이 여기서는 **남의 손님에게** 일어난다.

**넣을 것**

```
사장님께 전달 성공  →  손님에게 "접수됐습니다"
전달 실패          →  손님에게 "지금 접수가 어렵습니다. 전화로 부탁드립니다 (번호)"
                      그리고 실패를 로그에 남긴다
```

★ **전달을 확인하기 전에 손님에게 「됐다」고 말하지 않는다.**

### ③ 손님 원문이 평문으로 쌓인다

뭉클이가 스스로 짚었다. 맞다.

`chats.jsonl` 에 들어올 것 — **이름 · 전화번호 · 주소.**
*"010-xxxx-xxxx 로 연락주세요"* 는 문의에 흔하다.

사주에서 정한 규율 그대로다 — **필요한 것만 남긴다.**

| 남길 것 | 버릴 것 |
|---|---|
| 문의 유형(`kind`) · 시각 · 답한 내용 | **손님 원문** |
| 통계에 쓸 것 | 개인을 알아볼 수 있는 것 |

★ 기획서 「다음 단계 3」이 *"무엇을 가장 많이 물어보나 통계"* 인데,
  **그건 `kind` 만으로 된다. 원문이 필요 없다.**
  원문을 남기려면 그때 사장님·손님 동의가 필요하다.

**없으면 새어나갈 수도 없다.**

---

## 기동 전 권고 — 둘

### ④ N1 — 「없다」를 먼저 말한다

뭉클이가 *"kind 가 `menu_all` 인 것은 고칠 후보"* 라 했다.
**절반만 맞다.**

전체 메뉴를 보여주는 것 자체는 **장사에 옳다.**
*"없습니다"* 로 끝나면 손님이 돌아선다.

**문제는 「없다」가 빠진 것이다.**

```
✗  "저희 메뉴는 딸기케이크, 초코케이크, 치즈케이크입니다"
       → 손님은 티라미수가 있는지 없는지 모른 채 넘어간다

✓  "티라미수는 저희 메뉴에 없습니다.
     대신 딸기·초코·치즈 케이크가 있어요."
```

★ 이건 지어내기 방지가 아니라 **정직함**의 문제다.
  **묻는 것에 먼저 답하고, 그다음에 대안을 준다.**

### ⑤ 임시휴무 — 「모르는 것」보다 「안다고 착각하는 것」이 위험하다

JSON 에 영업시간이 있으니 봇은 **언제나 자신 있게** 답한다.
그런데 **오늘 임시휴무면?** 명절이면? 사장님이 아프면?

> **모르면 「확인 후 안내」로 빠지는데, 안다고 착각하면 그냥 틀린다.**

**넣을 것** — `stores/*.json` 에 `closed_dates: []` 한 칸.
사장님이 채우면 그 날은 *"오늘은 휴무입니다"* 로 답한다.
비어 있으면 지금과 같다. **한 칸으로 큰 사고를 막는다.**

---

## §5 규칙 기반은 한계가 아니라 자산이다 ★

기획서에 *"Meta Muse 의 국내 최소판"* 이라 썼다.
언젠가 **"LLM 을 넣으면 더 똑똑해지겠지"** 하는 날이 온다.

**그날 이 줄을 읽어라.**

| 지금 (규칙 기반) | LLM 을 넣으면 |
|---|---|
| 프롬프트 주입이 안 통한다 (N7 실측) | **통한다** |
| 없는 메뉴를 지어낼 수 없다 | **지어낼 수 있다** |
| 답이 늘 같다 — 사장님이 예상할 수 있다 | 매번 달라진다 |
| 왜 그렇게 답했는지 설명된다 | 설명이 어렵다 |

★ **남의 가게를 대신 말하는 물건이다.**
  똑똑한 것보다 **틀리지 않는 것**이 먼저다.

LLM 을 쓴다면 **답을 만드는 자리가 아니라 「무엇을 묻는지 알아듣는 자리」**에 쓴다.
그러면 지어내기가 들어올 틈이 없다.

---

## 빠진 것 하나 — 무엇이 되면 성공인가

기획서에 **성공 기준이 없다.**
없으면 「완성」을 판정할 수 없다. 어제 사주에서 배운 그것이다.

**제안 — 잴 수 있는 것 하나**

```
사장님이 안 봐도 되는 문의의 비율

지금        100% 가 사장님께 간다
목표        봇이 70% 를 끝내고, 30% 만 사장님께 올라간다
```

`kind` 별 집계로 바로 나온다. **원문 없이도 잴 수 있다.**

★ 그리고 이 숫자가 **두 번째 가게 영업 자료**가 된다.
  기획서 「다음 단계 3」이 정확히 그 얘기다. **좋은 감각이다.**

| | 무엇 | 조건 |
|---|---|---|
| 1 | ①②③ 을 넣는다 | **필수** |
| 2 | ④⑤ 를 넣는다 | 권고. 하루면 된다 |
| 3 | 성공 기준(70%)을 기획서에 적는다 | |

★ 5번이 중요하다. **첫 손님이 남이면 실수를 남이 겪는다.**
  아는 가게에서 일주일 돌려보고 남에게 연다.
