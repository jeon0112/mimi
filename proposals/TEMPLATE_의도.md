## 1. Problem — 누가 어떤 문제를 겪고 있는가

> 우리 문제가 아니라 **수요처의 문제**를 쓴다.
> "우리가 이걸 하고 싶다"는 Problem 이 아니다.

## 2. Proposed Outcome — 되면 무엇이 구체적으로 달라지는가

> 숫자로 쓴다. 못 쓰면 **왜 못 쓰는지**를 쓴다.
> 「활성화」·「제고」·「기여」로 끝나면 안 쓴 것이다.

## 3. Affected Users & Systems — 누가·무엇이 영향을 받는가

## 4. Constraints — 반드시 지켜야 할 제약 ★

여기가 이 문서의 핵심이다. **최소한 이 다섯 줄은 채운다.**

| 제약 | 값 | 확인처 |
|---|---|---|
| 지원금 총액 | | 공고 ○쪽 |
| **의무 이행 기간** | | |
| **현금인가 간접수행인가** | | |
| 자부담 비율·형태 (현금/현물) | | |
| 우리 인력 실투입 (사람 × 개월) | | |

**금액을 볼 때 의무 기간을 함께 본다.**
「간접수행」·「외주기관 직접 지급」은 **현금 사업이 아니다.**
— 2026-09-11 광주TP: 450만원에 5년 성과자료 의무. 초안까지 쓰고 철회했다.

## 5. Open Questions — 아직 답을 못 얻은 것 ★

| 미결 | 왜 중요한가 | 누가·언제 답하나 |
|---|---|---|
| | | |

**여기에 「이 실적이 누구 것인가」가 들어간다.**
— 2026-09-14 온디바이스AI(KETI): 전제로 삼은 실적이 협력사 것이었다. 철회.

빈칸으로 두지 않는다. 미결이 없으면 **"없음"이라고 쓴다.**
쓰지 않은 것과 없는 것은 다르다.
