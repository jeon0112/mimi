# 근거 원장

**단일 진실 원천.** 계획서의 모든 주장 문장은 여기 한 행을 가리킨다.
가리킬 행이 없는 문장은 쓰지 않는다.

## 근거유형

| 표기 | 뜻 | 계획서에서 |
|---|---|---|
| `실측` | 직접 재서 숫자를 얻은 것 | 그대로 쓴다 |
| `기록` | 커밋·로그·DB·문서에 남아 있는 것 | 그대로 쓰되 출처를 밝힌다 |
| `추정` | 근거 있는 산정 | **반드시 "추정"이라고 밝힌다** |
| `미측정` | 아직 재지 않은 것 | 쓰지 않는다. 재고 나서 쓴다 |

## 행 추가 규칙

1. **번호는 재사용하지 않는다.** 폐기하는 행은 지우지 말고 `상태: 폐기`로 표시하고 사유를 남긴다.
   계획서 초안이 이미 그 번호를 가리키고 있을 수 있다.
2. **측정시점을 반드시 적는다.** 6개월 전 숫자와 어제 숫자는 다른 무게다.
3. **출처는 다시 찾아갈 수 있게 적는다.** "내부 자료"는 출처가 아니다.
   커밋 해시, 파일 경로, 실행 ID, 문서번호를 적는다.
4. **수치가 없는 행은 만들지 않는다.** "경험이 풍부하다"는 근거가 아니다.

**E-10 주의** — 표본이 3건뿐이다. 계획서에 **표본 수를 반드시 함께 적는다.**
적은 표본을 큰 표본인 척하면 질의응답에서 무너진다.

**E-14 상세 — 네 번째 사례 (2026-09-06)**

AI 게이트웨이가 쓰던 z.ai API 키가 콘솔에서 삭제됐다. 프로세스는 재시작되지 않았으므로
**죽은 키를 손에 쥔 채 22시간 46분간 `Up` 상태로 떠 있었다.**

| | |
|---|---|
| 겉보기 | 컨테이너 `Up 23 hours` · 호스트 `up 9 days` · 프로세스 살아 있음 |
| 실제 | 모든 호출이 `401 code 1000` 으로 0.3초 만에 거부 |
| 증거 | 컨테이너 키 `b9b85…` 가 z.ai 콘솔 목록에 없음 (`b6b2…`/`d379…`/`20a0…`) |

**탐지까지 걸린 시간은 정직하게 구간으로 적는다.**
마지막 정상 응답 11:52, 로그의 첫 401 은 14:50. 그 사이 어디에서 시작됐는지는 모른다.
발견은 15:5x경 — 사람이 말을 걸어봐서 알았다.

```
MTTD = 1~4시간 (시작 시점 불확실)
```

**하나의 숫자로 적지 않는다.** 모르는 것을 아는 척하면 그 표가 통째로 못 믿을 것이 된다.

**이 사례가 원장에 주는 것**
- 앞의 세 건은 *자동화가 조용히 멈춘* 경우였고, 이건 *인증이 조용히 끊긴* 경우다. 유형이 다르다.
- 그리고 **사람이 말을 걸기 전까지 아무도 몰랐다.** 헬스체크는 초록불이었다.
  `Up` 은 프로세스가 살아 있다는 뜻이지 일을 하고 있다는 뜻이 아니다.
- → E-16(아래)의 근거가 된다.

## C. 에어가전 / 공조 — 비어 있음

채우려면 아래를 재야 한다. 없으면 없다고 쓰고, 있는 것만 쓴다.

| 필요한 근거 | 왜 필요한가 | 상태 |
